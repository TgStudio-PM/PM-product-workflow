# ADR 0001：采用分级维护授权

- 状态：已确认
- 日期：2026-09-07

## 背景

个人维护者若逐项人工审查所有 PR，长期成本会超过常规修改本身；完全自动合并又无法覆盖项目定位、开源边界和真实资料提炼中的产品判断。

## 决定

所有非微小变更继续通过 PR 留痕。低风险和中风险变更在差异自审、相关验证和开源边界检查通过后可以合并；高风险变更必须完成可审阅 PR，并由产品负责人明确确认后合并。

风险不确定时提高一级。不得以自动合并为由直接推送 `main` 或跳过检查。

## 理由

该方式保留变更历史和高风险人工判断，同时减少产品负责人对格式、链接和常规实现的重复审批。

## 后果

- 仓库必须维护明确的风险定义和 PR 验证记录。
- Coding Agent 需要在每次 PR 中说明风险等级及依据。
- 宪章、边界、License、真实资料提炼、重大不兼容、CI 与合并规则、正式发布始终按高风险处理。
- 产品负责人可以随时提高某次变更风险、暂停自动合并或替代本决策。
