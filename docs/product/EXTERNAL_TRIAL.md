# 工作流实践与反馈

本指南用于记录一次实际原型开发/迭代过程中的理解、阻塞和改进反馈。参与者使用自己有权访问的既有原型项目；如果从新需求开始，按项目约束建立本轮可评审的初始原型。无需切换到仓库提供的演示页面或工程。

## 实践一次需求迭代

1. 选择一项当前需求，说明目标、来源或确认责任人和受影响范围；关键信息未知时记录待确认。
2. 按项目现有入口查看相关事实、页面和代码，复用既有技术栈、设计约束和组件。
3. 与 Coding Agent 或开发者协作完成一项可评审的原型代码改动。
4. 由产品负责人按受影响业务路径核对结果，分别记录实际运行、静态检查和未执行内容。
5. 最小同步已确认事实、原型表现、版本差异、下一步；需要新会话续作时先核对实际现场并保留未提交改动，不重复已完成任务或已否定方案。
6. 按实际接收方判断是否需要交付材料；若有离线使用要求，再检查目标 `file://` 入口并独立验包。

可以只实践适用的任务，不强制固定步骤耗时、特定屏幕环境、离线包或三类交付。把 AI 静态阅读、机器/工程检查和参与者本人实际操作分开记录；AI 或静态检查不能代替产品业务验收。反馈模板中的项目都可标为未执行或待确认，不要求全部完成。

## 反馈与回传

复制[反馈模板](TRIAL_REPORT_TEMPLATE.md)，按实际证据记录目标、改动、业务路径观察、事实同步、接续结果、未决项和阅读难点。报告不需要包含源代码或私有项目文件。参与者和邀请者自行约定回传渠道；本仓库不要求公开提交试用材料。

使用者授权的私有资料留在自己的工作区；公开内容的处理要求见[开源边界](../../maintainers/OPEN_SOURCE_BOUNDARY.md)。
