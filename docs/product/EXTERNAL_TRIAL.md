# 外部朋友试用手册

这是一份给未参与本仓库开发的朋友使用的试用说明。你不需要是产品经理，也不需要安装 Node.js 或 Python。按你方便的方式完成一条或多条试用轨，并用[试用反馈模板](TRIAL_REPORT_TEMPLATE.md)记录实际操作；没有做的任务请写“未执行”。

## 可以转发的邀请

> 想请你独立试用这个公开原型工作流仓库：<https://github.com/TgStudio-PM/PM-product-workflow>。你不必是产品经理或开发者，也不需要提供真实项目资料。打开首页的“参与试用 / Try it”，按适合你的基础、AI 辅助、AI 单独评审或工程轨完成任意任务。请记录你实际打开、阅读、运行和亲自核对了什么；没做的步骤写“未执行”，遇到阻碍写“受阻”。完成后把填好的 `docs/product/TRIAL_REPORT_TEMPLATE.md` 副本回传给我。请先删除报告中的姓名、账号、路径、截图等个人或私密信息。试用结果用于改进说明，不代表正式发布验收。

## 对象、版本和边界

- **参与者：**任何未参与本仓库开发的朋友。报告中只需概括自己的角色和相关经验，不必写姓名或单位。
- **版本：**仓库当前标记为 v0.1 开发中，尚未正式发布。请记录你实际下载或克隆的仓库提交（commit）；不要把当前内容称为正式版。仓库变化后，反馈以你实际使用的提交为准。
- **隐私：**只使用仓库中的完全虚构材料申报案例。不要粘贴真实政务资料、客户信息、账号、密钥、私有对话或内部文件。回传前清理个人信息、本机绝对路径、浏览器个人资料和未脱敏截图。
- **记录：**每个任务使用“通过 / 未通过 / 未执行 / 受阻”之一，并写实际步骤、观察、期望与实际结果。报告模板可以复制到仓库之外填写；无需提交代码。
- **证据边界：**读到说明只证明你读到了说明；AI 对页面或代码的判断只代表静态评审。只有实际打开页面、运行命令或检查浏览器时才记录对应运行结果，并注明环境。不得把 AI 生成的猜测写成已观察事实。

## 轨道 A：基础阅读与离线案例（无需开发环境）

### 准备

在仓库首页选择 **Code → Download ZIP** 下载副本并解压，或使用你熟悉的方式克隆仓库。记录你使用的方法和提交版本。无需安装 Node.js、Python 或其他工具。

### 任务

先在浏览器打开 `examples/material-submission/index.html`。案例只用虚构内容；说明文字最多 500 字，不要输入真实个人或机构信息。逐步执行并在[反馈模板](TRIAL_REPORT_TEMPLATE.md)的“固定案例操作记录”中逐项选择状态、记下实际观察。页面交互使用当前浏览器本地状态；各浏览器对本地文件的支持可能不同，不保证都能运行。

| 步骤 | 操作 | 预期观察（以实际页面为准） |
| --- | --- | --- |
| 1. 检查并清理旧演示数据 | 如果页面恢复出先前的说明或材料选择，点“清除演示数据”并确认；如果没有旧数据，记下“未发现旧数据”后继续。 | 页面回到空白申请说明、未勾选材料和草稿状态。记录按钮不可用、确认框或状态与预期不符的情况。 |
| 2. 空表单提交 | 不填写说明、不勾材料，点“确认并提交”。 | 页面/浏览器提示必填说明，且没有提交。记录实际提示；若同时出现必备材料提示也记录，不要求所有浏览器显示相同提示。 |
| 3. 填写虚构说明并暂存 | 在申请说明填写例如“虚构演示：申请参加材料申报教学练习。”，点“暂存草稿”，再刷新页面。 | 说明仍显示，状态反映草稿；页面称数据保存在本地浏览器。记录刷新前后实际内容和状态。 |
| 4. 确认必备材料并提交 | 勾选“项目背景说明”和“迭代计划摘要”，保持“页面流程草图”可选项不勾选，点“确认并提交”。 | 页面显示提交完成，提交内容变为只读；记录页面实际状态及是否仍可编辑。 |
| 5. 清除并复位 | 点“清除演示数据”并确认。 | 说明、材料选择和已提交状态被清除，页面回到可重新填写状态。记录是否出现确认、清除结果及残留内容。 |

如果某一步之前就受阻，后续步骤标“未执行”或“受阻”，不要假设其结果。每一步失败或未做都要记录；通过只表示你在所记录的环境中观察到预期结果。

随后可阅读 `examples/material-submission/facts/module/ITERATIONS.md`、`DECISIONS.md` 和页面，比较案例三轮：第一轮初始决定、第二轮材料规则变化、第三轮只做事实核对/接续记录且没有改页面。阅读 `examples/material-submission/iterations/03-handoff-exercise.md`，辨认模拟接续记录与第三轮未重跑的浏览器验收。把难以区分的轮次、事实和当前页面表现也写入模板。

### 判断与反馈

每项按模板标状态。任务本身不要求你判断案例业务是否正确；重点是入口、说明、虚构边界和记录之间是否容易理解。如果浏览器不允许从本地打开，记录浏览器和提示并标记“受阻”，不要安装额外组件来绕过。

## 轨道 B：朋友亲自操作，AI 辅助（可选）

你亲自完成轨道 A 中至少一个任务，再把相关的公开仓库文件或链接交给 AI 请它协助理解。AI 是否能读取 GitHub、是否能访问本地 ZIP，取决于你使用的工具；必须记录它实际打开的文件、链接或你粘贴的内容。若没有可观察到的访问证据，写“未确认”，不要认为仅提供 URL 就代表 AI 已读完整仓库。

### 可复制提示词

```text
请只根据你当前实际能够打开的 PM-product-workflow 公开仓库内容，协助我理解下面的试用任务。

任务：<粘贴我正在做的具体任务>
我亲自看到或操作的内容：<写实际观察；没有就写“尚未操作”>

先说明你实际访问了哪些 URL、文件或我粘贴的文本，以及哪些内容无法访问。请分别列出：仓库文字明确写出的内容、你基于这些内容作出的推断、仍无法确认的问题。不要声称运行了页面、命令或浏览器检查；除非你确实执行并提供了可核对证据。请给我一个我可以亲自核对的下一步，不要替我填写试用结论。
```

### 可观察任务与记录

- 比较 AI 所说的仓库事实与实际打开的文件；记录一致处、差异和你如何核对。
- 观察提示词是否让 AI 说清访问范围、推断和未确认项；若 AI 声称读过或运行过而你无法核实，按“未通过”或“受阻”记录具体措辞。
- 由你亲自执行一个可行的基础任务，并单独记下你自己的观察。AI 建议不能代替这一步。

## 轨道 C：AI 单独静态评审（可选）

如果你只想让 AI 阅读材料，也可以把仓库链接或一份/几份公开文件交给 AI，不需要自己运行案例。此轨记录的是 **AI 静态评审**，不能作为真人可用性测试、页面运行、浏览器验收或产品验收。

### 可复制提示词

```text
请对 PM-product-workflow 的公开产品资料做 AI-only 静态评审。我不会运行页面或命令。只依据你当前实际能够访问或我实际提供的仓库内容，不要假定能访问整个仓库。

先列出你实际打开的 URL 和精确文件路径；把无法访问的路径单独列出。检查范围应包括：README/README.en.md、本外部试用手册与反馈模板、docs/product/README.md、项目/模块/可选模板、材料申报虚构案例的页面与三轮事实记录、第三轮接续练习、pm-prototype-handover 接续材料、交付指南、pm-prototype-packager 与 package-profiles。逐条注明哪些材料实际可访问；不要把未打开的路径当作已审查。

按宪章的四项 v0.1 成功标准分别评审：1) 新使用者能否从虚构案例理解完整迭代与交付流程；2) 能否使用模板建立项目事实源；3) 能否在新会话正确接续并避免重复已否定方案；4) 能否获得可离线运行并通过验包的交付物。每项给出可定位的文件路径和标题/段落作为支持证据，指出静态阅读无法验证的部分，并列出具体问题或待确认项。区分仓库明确事实、你的推断、无法确认；说明你没有做的运行或真人验收。不要声称运行了 HTML、浏览器或命令，不要编造试用者行为、反馈、测试结果或正式发布状态。

最后按“高 / 中 / 低”优先级整理文档理解问题。每条发现包含路径、定位、问题、可能影响和中性核对问题；如果证据不足或文件不可访问，明确写“无法静态判断”。
```

### 可观察结果

检查 AI 是否列出实际访问范围、引用具体仓库路径、覆盖四项成功标准并区分支持证据、静态验证限制和待确认问题。报告中注明“仅 AI 静态评审”；若 AI 无法访问仓库，则把实际提供的材料和受限范围写清。AI 没发现问题不代表文档已通过真人试用、运行验收或正式发布验收。

## 轨道 D：工程试用（可选，需开发环境）

这条轨道适合愿意运行 Vue starter 的朋友。它是工程试用，不属于非开发产品经理的“五分钟新增页面”人测目标。若你要参加该目标测试，须符合[新增页面人测卡](../../starters/vue-prototype/docs/ADD_PAGE_TRIAL.md)的角色门槛，并完整遵守卡内计时定义；其他参与者的结果不能填作该人测。

### 环境与入口

- 需要 Node.js 20.19+ 或 22.12+、npm 和可用终端；常见操作系统均可，记录实际系统与版本。
- 进入仓库中的 `starters/vue-prototype/`，依照其中 [`README.md`](../../starters/vue-prototype/README.md) 的安装和命令说明操作。
- 可选任务入口：[`docs/ADD_PAGE.md`](../../starters/vue-prototype/docs/ADD_PAGE.md)、[`docs/ADD_PAGE_TRIAL.md`](../../starters/vue-prototype/docs/ADD_PAGE_TRIAL.md)。首次在新模块建立事实文件时，可以按说明运行 `npm run facts:new -- demo-help`；该命令只复制空白事实模板，不会替你确认业务规则。
- 报告实际执行的命令和结果。不要因为 README 列出命令就声称自己运行过；浏览器验证仅记录实际使用的浏览器与结果。

### 任务与可核对结果

| 任务 | 预期可核对结果 | 失败或受阻时记录 |
| --- | --- | --- |
| 按 starter 说明安装依赖并启动 | 命令实际结束，记录退出结果；若启动成功，记录本地页面是否可打开 | 命令、Node/npm 版本、错误摘要及未完成步骤 |
| 阅读并可选执行 `page:new` 与 `facts:new` | 记录实际使用的命令、生成路径以及空白事实与已确认规则的区别 | 记录每一步及文件证据；不要推断命令的外部效果 |
| 可选完成新增页面任务 | 按人测卡检查导航、刷新、内容和所需回归，并按卡规定记录用时 | 若不符合人测角色门槛，标明工程试用，不填写“五分钟目标达成” |
| 可选运行类型检查或预览打包 | 每条实际运行命令有单独结果；静态包检查和浏览器交互分开记录 | 保留命令失败摘要；未运行的命令标“未执行” |

构建、静态包审计、`file://` 页面交互是不同的观察。不要把其中一项通过写成其他项也通过；本仓库不提供真实 API、身份认证、文件上传或生产办理能力。

## 回传

复制[试用反馈模板](TRIAL_REPORT_TEMPLATE.md)，按实际情况填写后通过邀请你的人约定的渠道回传。没有约定渠道时，先询问邀请者；不要把报告、截图或本机材料直接提交到公开仓库。反馈应说明哪些步骤让你停顿、哪些词或链接难懂、你期望看到什么，以及实际看到什么。请清理个人信息和私密路径；只提供确有必要且已脱敏的文件证据。
