# 产品工作流入口

本产品面向政务与复杂 B 端产品经理，支持与 Coding Agent、开发者协作进行桌面 Web 原型开发和持续迭代。已有原型优先；也可从明确需求建立首版原型。方法不要求特定框架、设计系统或工具。

## 从本轮需求开始

阅读[原型需求迭代与接续指南](PROTOTYPE_ITERATION.md)，把本轮目标、需求来源和可访问的项目路径提供给 Agent。沿用项目现有入口、技术栈、设计约束和组件，先查影响，再实现本轮原型改动并按业务路径验收。

如从需求开始建立初版原型，先确认目标用户、角色与流程、设计约束及技术栈。对缺失的关键规则、字段、接口和运行条件提出待确认项，不在此工作流中承诺开箱可运行的应用脚手架。

## 在已有项目中接入

1. 读取项目已有的 Agent 入口、事实记录和当前原型；只盘点本轮相关页面、数据、组件和约束，优先复用现有材料。
2. 给出本轮需求、来源或确认责任人、目标版本，以及相关原型和事实文件路径。
3. 分析影响范围并列出冲突、未知项；明确部分可直接实施，关键缺口先请负责人确认。
4. 在现有项目中完成代码改动，由产品负责人按受影响业务路径检查。
5. 在相关事实记录中最小同步已确认变化、原型表现、版本差异和下一步；按需准备接续或交付。

可选地复制[项目入口模板](../../templates/project/AGENTS_TEMPLATE.md)，只补足真实路径指针；已有入口不要覆盖。项目和模块模板按需选择，不要求为每次迭代新建全部文档。

## 工作流资源

- 三个现有 Skills：[`pm-prototype-memory`](../../.agents/skills/pm-prototype-memory/SKILL.md)、[`pm-prototype-handover`](../../.agents/skills/pm-prototype-handover/SKILL.md)、[`pm-prototype-packager`](../../.agents/skills/pm-prototype-packager/SKILL.md)。按任务选用，见[Skills 使用说明](USING_SKILLS.md)。
- 项目/模块事实模板：`templates/project/`、`templates/module/`。
- 可选政务与复杂 B 端预设：[gov-enterprise-cn](../../profiles/gov-enterprise-cn/PROFILE.md)。
- 需要向接收方交付时，按[打包说明](PACKAGING.md)复制并定制交付配置模板。

需求确认、原型观察和已核对实现分别记录。不得从代码推断已确认需求；未知业务或技术契约保持待确认。

## 验收与接续

产品负责人检查本轮业务路径、状态和边界。代码检查、构建、包审计、浏览器操作分别记录；仅在目标交付要求离线使用时，才需在接收方目标环境检查 `file://` 入口和核心路径，并独立验包。根据接收方选择必要交付，不要求每轮都生成包。

主任务是原型需求开发/迭代、业务验收、事实同步和可用接续。AI 静态阅读或机器检查不能代替实际业务验收。
