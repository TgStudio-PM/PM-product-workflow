# 产品工作流入口

本指南面向使用 Coding Agent 持续设计和迭代政务与复杂 B 端桌面 Web 原型的产品经理。开发者可以参与实现和交接；Vue、特定模型或设计体系都不是使用前提。手机适配可以按项目需要处理，但不是本工作流的主要目标。

## 从一次需求迭代开始

先阅读[原型需求迭代与接续指南](PROTOTYPE_ITERATION.md)。它说明如何从需求变化出发，分析影响、在现有原型上完成可评审改动、验收业务路径、同步事实并按接收方交接。

## 适用场景

- 需求持续变化，需要保留原因、影响范围和待确认事项。
- 原型跨多个页面、入口、角色、字段或状态，需要在既有项目中迭代。
- Coding Agent 协作跨会话持续进行，需要避免重复已否定方案并保留可核对交接。
- 产品经理需要把原型、需求事实和实现说明交给不同接收方。

## 如何开始

1. 在自己的项目仓库建立项目和模块事实源。可以复制 `templates/project/` 与相关 `templates/module/`；只按实际需要增补内容。项目背景保留稳定范围与阶段，具体任务进度、待办和下一步放在模块 `CURRENT.md`，避免重复维护。
2. 为当前变更找出相关页面、非导航入口、角色、字段、状态、数据和共享组件。原型导航仅展示可访问入口，不是完整需求清单。
3. 阅读[迭代指南](PROTOTYPE_ITERATION.md)，给 Coding Agent 提供本轮目标、相关事实路径、确认责任人和边界。
4. 在现有原型和工程框架中落实变更，并由产品负责人按目标业务路径检查。
5. 按证据更新事实和版本差异，选择下一步或交付对象。小改动写短记录；不必机械改动所有模板。

使用者自己的授权私有项目资料保留在自己的工作区。不要复制真实资料、私有对话、本机路径或生产信息到本公开仓库。

### 可选的项目入口

如果自己的原型项目还没有 `AGENTS.md`，可按需复制[使用者原型项目入口模板](../../templates/project/AGENTS_TEMPLATE.md)到项目根目录并命名为 `AGENTS.md`，再确认 `PROJECT_CONTEXT.md` 和 `MODULE_REGISTRY.md` 的真实位置并调整指针。已有入口保留原文，只合并所需路径指针，不要覆盖。不能假定所有 Coding Agent 都会自动发现该文件；若未自动读取，请在任务中明确要求读取。本入口不自动发现或安装 Skills。

可复制的短提示词：`在<我的原型项目根目录>继续原型迭代。先读本项目AGENTS.md，按模块事实核对现场后继续<任务或未完成项>。`

## 事实与 Skills

项目事实按来源分类：需求与规则的确认状态、原型当前表现、已核对实现说明分别记录。出现差异时并列写明来源和待确认项；未知版本或来源保持“待确认”。不能从代码反推已确认需求，也不能把原型或 mock 表述成生产能力。

三个现有 Skills 支撑同一工作流：`pm-prototype-memory` 管事实与变化，`pm-prototype-handover` 管接续，`pm-prototype-packager` 按用途准备交付材料。见[如何串联使用 Skills](USING_SKILLS.md)。

## 验收与交付

产品验收检查角色、规则、状态和业务路径；机器检查、构建、静态资源审计和浏览器运行分别记录。静态包结构或 HTTP 检查不证明 `file://` 离线可用。若交付要求离线预览，必须在接收方目标环境实测入口和核心路径，并按[交付指南](PACKAGING.md)独立验包。按接收方需要选择材料，不要求每项任务都制作全部交付包。

独立非开发产品经理完整主任务试用尚未完成；仓库状态和历史验收边界见 [`maintainers/CURRENT.md`](../../maintainers/CURRENT.md)。阅读完全虚构的[材料申报案例](../../examples/material-submission/index.html)或使用可选的[Tg Studio Vue starter](../../starters/vue-prototype/README.md)，都不能代替目标使用者人测。
