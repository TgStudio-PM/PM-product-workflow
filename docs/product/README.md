# 产品工作流指南

本目录面向使用 PM-product-workflow 的产品经理和协作开发者。根目录 `AGENTS.md`、`maintainers/` 和 `.github/` 用于维护本开源仓库，不是产品工作流的必读内容。

## 建立自己的项目事实源

1. 将 `templates/project/` 复制到自己的项目仓库，填写项目背景、模块清单和设计规范。
2. 每个持续迭代的模块复制一份 `templates/module/`。
3. 参考 `profiles/gov-enterprise-cn/` 选择或编写适合项目的设计预设。
4. 让 Coding Agent 先读取项目级文件，再按任务读取相关模块文件。
5. 每轮完成后同步事实、分别记录产品验收与机器验证。

对应文件：

| 层级 | 文件 | 保存内容 |
| --- | --- | --- |
| 项目 | `PROJECT_CONTEXT.md` | 目标、范围、角色、约束和事实来源 |
| 项目 | `MODULE_REGISTRY.md` | 模块状态、入口和负责人 |
| 项目 | `DESIGN_PROFILE.md` | 当前选择的设计规范及覆盖规则 |
| 模块 | `CURRENT.md` | 稳定基线、正在进行、下一步和阻塞 |
| 模块 | `BUSINESS_RULES.md` | 已确认规则与待确认问题 |
| 模块 | `PAGE_FLOW.md` | 页面、角色、状态和操作流程 |
| 模块 | `DECISIONS.md` | 重要取舍、理由和影响 |
| 模块 | `ERROR_LEDGER.md` | 重复错误、根因、无效尝试和验证 |

## 每轮迭代

```text
读取必要事实 → 确认本轮目标 → 修改原型与规则
→ 产品验收 → 机器验证 → 同步状态 → 交付或接力
```

- 需求、业务规则或流程改变时，同步对应事实文件。
- 源码和页面只能证明当前实现，不能自动覆盖已确认需求。
- 无法确认的内容标记为待确认，不用合理猜测补齐。
- 同一问题两次等价尝试仍失败时，停止盲试并记录稳定复现、无效方案和下一项可验证假设。

## 新会话接力

新会话只需要读取项目级事实、相关模块事实和当前任务，不依赖完整聊天记录。建议提供：

```text
【任务】本轮目标
【当前基线】版本、分支或可运行入口
【已完成】已经落地的内容
【已验证】产品验收与机器验证
【未完成】剩余工作和待确认问题
【下一步】下一项可直接执行的动作
【禁止事项】已否定方案和边界限制
【影响范围】相关页面、规则和文件
```

## 验收

- **产品验收**：术语、规则、角色、状态、流程和交互结果。
- **机器验证**：测试、构建、浏览器运行、链接、资源和交付包检查。

两类验收都满足，才能把结果写成新的稳定基线。未执行的验证必须明确记录，不用笼统的“已完成”替代。
