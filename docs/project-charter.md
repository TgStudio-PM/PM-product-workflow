# 项目宪章

本文件记录 PM-product-workflow 的长期使命、定位和明确边界。内容极少变更；修改属于高风险，必须由产品负责人确认。

## 使命

为使用 Coding Agent 设计复杂业务原型的产品经理提供一套可追溯、可接续、可交付的工作流，使长期协作不丢业务事实、产品决策和验证证据。

Codex 是首版参考实现，公开方法不绑定单一模型或工具。

## 定位

- 主要服务政务与复杂 B 端产品经理，开发者可以协作使用。
- 核心机制可以迁移，默认维护 `gov-enterprise-cn` Profile。
- 交付形态是方法、模板、Skill、检查工具和完全虚构的教学案例。

## 核心原则

1. Repository is memory. Conversation is working context.
2. 事实必须有来源，并区分已确认、待确认和当前实现。
3. 按需读取上下文，不把全部历史塞进每次会话。
4. 改动同步规则，错误形成闭环，验证分层表达。
5. 优先完善现有流程，再增加 Skill、Agent 或治理文件。

## 明确不做

- 不公开或改名包装任何真实项目材料、代码、截图、数据和对话。
- 不绑定前端框架、设计系统或 Coding Agent。
- 不建立自动语义裁决、全量对话同步或向量记忆库。
- 不提供生产接口、真实权限系统或真实后端。
- 首版不承诺 C 端、移动端和多设计体系的成熟预设。
- 不在缺乏证据时承诺性能或成本改善比例。
- 不复制无明确许可的第三方规范、代码和资产。

## v0.1 成功标准

不了解作者历史对话的新使用者仅凭公开仓库即可：

1. 通过虚构案例理解完整迭代与交付流程。
2. 使用模板建立自己的项目事实源。
3. 在新会话中正确接续，避免重复已否定方案。
4. 获得一个可离线运行并通过验包的交付物。
