# 可选执行任务包

用于把边界已锁定的确定性改动交给开发者或执行型 Coding Agent。按任务填写并提供本文件链接；小改动或单人协作可直接继续原型迭代，无需使用。需求、业务取舍、范围决策和最终验收仍由主线负责人处理。当前工具支持委派且分工有收益时再使用执行型 Agent；不支持时可由当前会话或开发者沿用相同边界执行。

## 任务

- **目标与完成行为：** <改完后用户能看到或完成什么；怎样算完成>
- **项目：** <项目/模块名称>
- **项目根路径：** <实际绝对路径；以下相对路径均以此为基准>
- **实际基线：** <分支、提交或版本，以及已检查的工作区状态；列出未提交改动>

## 依据与边界

- **最小必读证据：** <路径及用途；仅列完成任务所需内容>
- **已定方案：** <链接到权威正文及相关章节；没有则写“无”>
- **允许写入：** <明确文件或目录>
- **只读参考：** <明确路径>
- **禁止触碰：** <路径、行为、接口或共享规则；无则写“无额外限制”>

先核对实际现场并保留既有未提交改动；不要覆盖或回滚他人工作。只实现列明的目标和范围。缺少关键业务或技术事实、发现方案冲突、改动将越界时，回报证据并暂停依赖该问题的部分；其它独立部分可继续。不要猜测未确认的规则、接口或生产行为。

同一文件、模块或共享状态/规则的写入须串行；只有范围互斥且无共享依赖时才按需并行。是否委派及并行由负责人决定，不要求每项任务拆分。

## 验收与回传

- **机器验收命令：** <可复现的命令及预期结果；未执行项标“未执行”>
- **产品/环境验收：** <由谁按哪些页面、角色或业务路径检查；机器检查不能替代>
- **已执行验证：** <命令、结果；分别标出未执行或待人工复核的项目>
- **回传：** 完成状态；结果摘要；改动文件；验证结果；遗留阻塞或风险。

失败或中断后，先核对当前差异、已落地文件和验证状态，再决定是否续作；不得盲目重做或覆盖。若重复错误涉及交付、事实、文件安全或验证结论，沿用项目现有错误记录并链接记录；等价尝试连续两次失败后停止重试，固定现场并报告。

负责人收回任务后核对实际差异、范围和验证证据，不以执行者自报完成代替复核；产品验收由负责人按上述业务路径完成并记录。
