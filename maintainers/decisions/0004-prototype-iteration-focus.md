# ADR 0004：聚焦原型需求开发迭代

- 状态：已确认
- 日期：2026-10-29
- 替代：不替代既有 ADR。聚焦项目使命和 v0.1 成功标准；ADR 0002 的合并与 Release 授权及 ADR 0003 的导航范围继续适用。

## 背景

2026-10-29，用户明确纠正产品定位：PM-product-workflow 应聚焦产品经理实际进行原型需求开发迭代，优先桌面 Web，响应式检查作为补充。现有 Skill、模板、Profile、工程和教学案例用于支撑主流程；小型演示不能代表使用者实际原型质量，案例是辅助材料。可以吸收开发实现反馈，但不能将真实源码或业务内容复制公开。

本决定仅依据上述通用用户要求及仓库现有治理事实，不引入真实项目资料。独立非开发产品经理完整人测仍待完成；不得因缺少人测而降低验收标准，也不得将历史工程演练重新计算为新标准通过。

## 决定

- 将产品主线明确为：梳理需求变化 → 澄清影响 → 复用既有框架改动原型 → 按业务路径验收 → 同步事实及版本差异 → 按接收方交接；开发实现反馈回流后核对证据并进入后续迭代。
- 以既有桌面 Web 原型为优先使用场景，响应式检查按实际受影响范围补充。继续使用现有 Skill、模板、Profile 与工程作为支撑，不把继续扩建大型演示作为主线价值。
- 虚构案例用于解释方法和辅助学习，不作为真实原型质量指标。吸收开发反馈时区分需求、原型表现和已核对实现说明；不得公开真实源码、业务内容或内部材料。
- v0.1 四项成功标准为：
  1. 明确需求变更、分析影响，并在既有桌面原型上完成可审阅迭代。
  2. 事实有证据，区分已确认需求、原型行为、实现说明及版本差异，并注明来源。
  3. 新会话可从记录接续，并避免重复已否定方案。
  4. 按接收方提供适用成果；交付验收仍保留目标浏览器离线预览和独立验包。
- 独立非开发产品经理完整主流程人测仍为待完成事项。AI、浏览器自动化、工程演练及非目标用户反馈均不能替代。
- 新增简单页面的五分钟演示只作为辅助工程观察。保留原计时记录及其原始含义，不重算、不改标为新标准或产品价值验收通过。
- ADR 0003 关于静态导航、离线预览及不预先扩展 schema 等约束继续有效；不修改旧 ADR。正式 Release 仍需另行明确授权，自主合并授权保持不变。

## 理由

产品核心价值应由产品经理能否将明确需求变化转成可审阅、可验收、可追溯并能交接的原型迭代来衡量。示例和工程资产可以帮助学习与交付，但它们不能证明实际需求迭代质量。保留既有浏览器离线预览、独立验包及独立 PM 人测要求，避免把范围聚焦误解为降低验收门槛。

## 后果

- [项目宪章](../PROJECT_CHARTER.md)与[当前状态](../CURRENT.md)采用上述定位及验收口径；产品流程细节见[原型需求迭代与接续指南](../../docs/product/PROTOTYPE_ITERATION.md)。
- 下一步以有明确范围的需求变化迭代和独立使用者反馈为主，不以继续打磨演示替代主流程验证。
- 当前 `file://`、真机缩放和截图证据限制仍按具体记录呈现；HTTP、自动化密度模拟及过期版本证据不替代目标交付物的实际离线验收。
- 真实项目源码、业务资料和对话仍受[开源边界](../OPEN_SOURCE_BOUNDARY.md)禁止公开条款约束。

## 验收与待办

- 将新定位及四项标准同步到宪章和当前状态，并与产品指南保持一致。
- 保留真实产品验收边界：独立非开发产品经理主流程人测未完成；原生案例和新版 Vue starter 的 `file://`、Windows 真机 2K/125% 缩放未完成；本地 HTTP 结果不能替代这些检查。
- 保留 ERR-20261028-002 对四张被覆盖初始截图撤销验收用途的限制；无未关闭错误不等于产品人测完成。
