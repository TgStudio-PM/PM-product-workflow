# ADR 0003：原型导航架构范围

- 状态：已确认
- 日期：2026-10-28
- 替代：不替代既有 ADR；细化可选 Vue 原型模板的导航演进范围，并与 [ADR 0002](0002-delegated-merge-authority.md) 的合并授权并行适用。

## 背景

2026-10-28 收到四份外部 AI 评审与建议，讨论了 Vue 原型模板的信息架构、导航字段、页面生命周期、前后端边界、脚手架、模板版本和试用证据。它们是评审意见，不是新增测试或产品需求。决策以当时公开 `main`（`84bdebc`）及已记录的外部评审取舍为依据，同时考虑 Vue starter 的使用门槛和当前规模，避免维护机制超过产品本身。

当前模板以静态 `pageRegistry` 驱动路由、菜单和离线页面清单；组件静态导入、Hash 路由及 IIFE 静态预览支持 `file://` 使用。导航事实没有独立 IA 主表。针对未知 Hash 或已知页面路径携带 query 后被静默送回首页的问题，已决定作有限的导航行为修复，并补上当前导航项的 `aria-current` 语义。下列行为决定不代表代码修复已完成；实施和验收另按任务记录。

## 决定

### 立即处理

- 保留静态 `pageRegistry`，继续作为 router、menu、`PAGES.md` 和 manifest 的共同页面清单来源。
- 保留静态组件导入、Hash 路由及 IIFE 本地离线预览；不为此次导航问题引入路由框架或动态加载。
- 仅修复已复现的未知 Hash 与已知 path 带 query 时误回首页的问题，并为当前导航项增加 `aria-current`。
- 查询参数放在页面链接中，登记的 `path` 只保留静态路径；构建与独立验包同步拒绝把 `?` 参数写进登记路径。
- 将项目需要记录的导航组织约定放入已有 `PAGE_FLOW`，避免另建重复的 IA 主表。
- 在 API 对接模板中补充菜单、路由来源（前端静态或后端提供）待确认项。未获前后端及产品确认前，不预设生产菜单或权限行为。

### 后续条件性评估

- 如果实际出现稳定页面标识（pageId）及页面目录与菜单定义分离的需求，再在单一模块试点；届时同步评估脚手架、AST 静态解析、构建和离线验包，并提供适用迁移说明，不预先承诺固定版本方案。
- 只有在多模块查找或导航改动的具体问题被使用证据确认后，才评估 `group` / `order`；不因评审中的规模预测直接扩充 schema。

### 暂缓

- 域、模块、页面三级 IA 树；页面生命周期状态及按状态切片打包；角色场景引擎；动态 import；空 remote Repository。
- `page:remove`、`page:rename` 等可能改变或删除使用者文件的脚手架，模板版本与迁移治理框架，以及没有已证实维护障碍支撑的自动扫描或 CI 扩展。
- 将 `ITERATIONS.md` 设为每个模块或 `facts:new` 的强制模板。案例中的迭代记录仍可作为教学材料，是否需要通用模板待目标使用者反馈验证。

### 不采纳

- 不因外部 AI 建议恢复高风险 PR 的逐项人工合并审批；继续执行 ADR 0002。该授权不包含正式 Release，Release 仍须另行明确授权。
- 不因缺少独立非开发产品经理人测而临时降低或改写 v0.1 验收标准；AI、自动化或非目标用户的结果不能替代该项证据。
- 不将四份报告的状态描述、推测或未复现问题抄写为当前测试结论或仓库事实。

## 理由

当前静态注册表让页面导航、路由和离线清单保持一致，符合产品经理快速迭代与静态交付目标。先修复明确复现的路由反馈，并复用已有页面流程事实载体，可以改善体验而不制造第二套导航事实源。更复杂的分组、角色、状态和交付切片模型应由实际使用问题驱动，并经过完整的构建及离线验包验证。

## 后果

- Vue starter 继续保持可选参考工程，其导航能力不宣称具备真实认证、授权或后端菜单。
- 普通未知路由应提供可理解的反馈；静态注册表与本地离线预览仍是架构约束。
- 若后续证据触发 schema 试点，必须将使用者迁移成本、脚手架行为、AST 校验和所有离线交付检查纳入同一验证范围。
- `maintainers/acceptance/2026-10-26-external-review-triage.md` 的证据分层和最小修正原则继续有效；本记录只补充导航范围，不重写其结论。
