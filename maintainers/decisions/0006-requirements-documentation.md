# ADR 0006：增加按需开发需求文档能力

- 状态：已确认
- 日期：2026-11-04
- 替代：仅扩展 [ADR 0005 第 3 点](0005-workflow-only-product.md)“不开新公共参数或 Skill”的当期限制；ADR 0005 其他结论继续有效。

## 背景

用户批准盘点工作流后，确认需要补充面向前端、后端和 QA 的开发需求文档能力，帮助原型变化形成可审阅的开发交接。该补充不改变产品定位，也不重启 demo。

## 决定

新增 `gov-requirements-doc-writer` Skill，面向政务与复杂 B 端桌面 Web 原型，支持文档编写、增量更新和评审，默认 `dev-handoff`，另提供 `lean-delivery` 与 `custom` 模式及单一原创可裁剪模板参考。它只处理文档，不修改业务代码、不做 UI 改造、不自动打包。

与现有能力分工：memory 管有来源的事实和变化；本 Skill 将授权证据组织为开发需求文档；handover 管会话接续；packager 按实际需要准备白名单包。可按任务独立选用，不要求串行使用全部 Skills。

已确认需求、当前实现证据、差异和待确认契约须分别表达。关键业务缺口不得臆造；业务语义由产品确认，技术契约由相关前后端确认。文档或静态检查不代表联调。优先引用已有权威事实，保留用户材料在授权工作区，不在公共仓库复制。

## 理由

开发交接补足需求变化到协作开发之间的文档需要，同时维持原型开发与持续迭代主线。独立 Skill 可以按需调用，不把营销 PRD 或文档生成变成每轮强制步骤。

## 后果

更新 Skill 使用入口、产品说明、迭代指南、打包材料指引和当前能力清单。新增方法不增加打包必需文件、字段或 CLI。独立非开发产品经理实际验收仍未完成。

公开版依据公开仓库原则和通用任务要求全新编写，不复制本机旧 Skill 正文、私有模板、真实项目材料或第三方资产。前期本机盘点只用于确定候选能力，不用于再分发原件。

## 待验收

独立非开发产品经理仍需在其授权原型项目中实际试用完整工作流；本次机器检查不代表该产品验收。
