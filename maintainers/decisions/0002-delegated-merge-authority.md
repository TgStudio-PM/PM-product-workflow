# ADR 0002：委托 Coding Agent 决定 PR 合并

- 状态：已确认
- 日期：2026-10-24
- 替代：ADR 0001 中“高风险 PR 须产品负责人逐项确认后合并”的条款；其余风险分级与 PR 留痕原则继续有效。

## 背景

维护者希望后续 PR 合并不再逐项等待人工批准，由 Coding Agent 根据任务差异、风险和验证证据自行作出合并决定。此前 ADR 0001 将高风险 PR 的人工确认设为强制门槛，需同步更新当前维护入口，避免新会话沿用旧规则。

## 决定

- 所有风险等级的非微小变更继续通过 PR 留痕，不直接推送 `main`。
- Coding Agent 在完成风险判断、差异自审、开源边界检查及适用验证后，自行决定是否合并；不逐项请求产品负责人批准。
- 高风险变更需在 PR 中说明升级依据，并加强来源/授权、兼容性、文档同步和验证审查。风险不确定时提高一级。
- 验证失败、事实冲突、来源或授权不清、敏感信息命中未解决或开源边界无法判断时，保持未合并并说明缺少的证据。
- 禁止真实项目材料、数据、源码、截图、内部规则和对话进入公开仓库的红线不变。第三方素材仍需可核验的许可证和再分发依据。
- 本授权只涉及 PR 合并；创建正式 GitHub Release、发布包或对外发布声明须单独取得明确授权。

## 理由

PR、检查结果和决策记录仍提供可审查的变更历史；维护者将常规与高风险 PR 的合并判断持续委托给 Coding Agent，减少重复审批等待。严格的证据不足即停规则保留在授权范围内。

## 后果

- 根 `AGENTS.md`、维护政策、接力流程、贡献指南及 GitHub 模板以本决策为当前规则。
- PR 仍须列出风险等级、依据、产品验收、机器验证和开源边界结果。
- 自动合并不等于自动发布，也不允许跳过 PR、CI 或来源/授权审查。
- 维护者可后续明确暂停或替换本决策；旧 ADR 保留为历史记录。
