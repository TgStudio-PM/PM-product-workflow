# ADR 0005：聚焦原型开发与持续迭代工作流

- 状态：已确认
- 日期：2026-11-04
- 替代：替代 ADR 0003/0004 中把 Vue starter、固定案例、演示和相关专项验收作为当前产品入口或通用门槛的部分；不替代其中可复用的原型迭代原则、已发生的工程事实、ADR 0002 合并授权或正式 Release 授权规则。

## 背景

用户明确指出单页 demo 的质量明显低于实际原型，重复的虚构提示也影响产品观感；因此决定取消面向使用者的固定 demo，产品专注原型开发和持续迭代。既有公开材料中包含材料申报单页、Vue starter、固定试用轨道及与之绑定的产品入口和验收要求，容易让使用者把演示工程误认为产品能力或真实迭代质量。

## 决定

1. 产品面向政务与复杂 B 端产品经理、Coding Agent 和开发者协作；以需求变化推动原型代码开发/迭代成果为主线，事实、接续和按需交付为支撑。
2. 退出对外 demo 和 Vue starter 产品入口，不建立同等替代展示站。工作流优先复用使用者已有项目 stack、设计约束和组件；从新需求开始时只要求明确必要输入，不提供通用应用脚手架。
3. 保留现有 Skills、项目/模块模板、可选 gov Profile 和通用打包器；三类包配置仅作为需复制到使用者项目并按证据定制的模板。不开新公共参数或 Skill。
4. 验收主链仍为：需求影响和原型代码成果；有来源的事实与版本差异；需要时的新会话接续；向实际接收方提供适用材料。独立非开发产品经理在其授权原型上的完整试用尚未取得；旧 demo、AI 结果和工程记录不计为该验收。
5. 移除固定 demo 五步、指定屏幕环境、每项任务都制作离线包等本仓库统一门槛。若具体使用者交付要求离线使用，仍须在目标环境实测 `file://` 入口和核心路径并独立验包；不降低目标项目环境及业务验收。
6. 旧 Win2K/125% 等 demo 专项未完成保持未通过/未验证的历史状态，不标为通过；退役 demo 后它不再是当前统一门槛。既有验收和错误记录保留，不将旧记录改写成新位置或新结果。
7. 正式 Release 仍须另行明确授权。

历史链接为保全旧引用，可固定到 `a66a8599d22b10d8511aa5f74e7317d7ce92aa10` 快照；该快照仅证明链接目标在该提交存在，不表示该提交通过每条历史记录中的测试。各验收记录自述的受测版本仍是对应结论范围。

## 理由

高质量实际原型开发与迭代才是目标价值。固定 demo 会把注意力带回演示页面，也使通用工作流误绑定某个技术实现。通过保留通用方法和按证据定制的交付工具，可继续支持真实项目迭代，同时让展示内容与使用者项目质量脱钩。

## 后果

已有项目若曾从 Vue starter 派生，仍可作为使用者的既有原型接入；无需更换技术栈或重写业务。本次退役的是本仓库继续对外维护的应用模板和试用入口。旧源码及许可文本仍保留在 Git 历史，未修改的 package.py 仍可独立验证既有 ZIP。

- 产品入口、试用说明、反馈模板、贡献指南、宪章和当前状态应同步到工作流定位；删除 Vue 概览评审示例，保留通用 gov Profile 检查点与 REVIEW_TEMPLATE。
- acceptance/errors 的历史 Markdown 链接固定到原提交快照；纯文本历史路径、测试数量、失败记录和结论不改写。
- 演示专属 CI 与集成测试随演示产品退出；通用工具和配置使用临时最小输入验证，工程结果以对应变更记录为准，不预先宣称 CI 通过。
- 机器或 AI 验证不等于独立产品经理验收；具体交付环境结果按任务实际记录。

## 待验收

独立非开发产品经理仍需在自己有权访问的原型项目中完成四项工作流主链。未完成前不得宣称 v0.1 产品验收通过；该状态不阻止基于可复现问题继续工程改进。
