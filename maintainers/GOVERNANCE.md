# 治理规则

本文件规定信息如何分层、发生冲突时如何处理，以及何时同步文档、记录决策和关闭错误。

## 信息层级

| 层级 | 内容 | 载体 | 生命周期 |
| --- | --- | --- | --- |
| L3 | 项目级事实 | 宪章、边界、治理和维护规则 | 长期，极少变更 |
| L2 | 模块级事实 | Skill、Profile、模板、ADR、模块文档 | 长期，随能力演进 |
| L1 | 任务级上下文 | Issue、PR、任务描述和接力块 | 任务周期 |
| L0 | 对话上下文 | 当前聊天 | 临时，不作为长期事实源 |

## 冲突处理

- 低层信息不得静默覆盖高层事实。
- 用户明确确认的新决策代表最新意图，可以修改旧规则，但必须走对应风险流程、同步权威文件并记录 ADR。
- 同层材料发生冲突时并列记录差异，核对后处理，不擅自选择方便实现的一方。
- 源码和页面说明当前实现了什么，不自动证明产品需求正确。
- 无法确定时标记为待确认，停止不可逆或公开操作。

## 文档同步

每轮结束必须回答：

1. 改变了什么？
2. 哪些规则、页面和文档受影响？
3. 验证了什么，什么没有验证？
4. 下一次从哪里继续？

业务规则、决策、流程或验收标准变化时必须同步对应事实。纯文字、格式或不改变语义的调整可以声明无需同步及理由。

`maintainers/CURRENT.md` 只在里程碑、稳定基线、下一步、阻塞或未关闭错误变化时更新，不因错别字等微小修改机械更新。

## 决策记录

- 重要且长期有效的取舍写入 `maintainers/decisions/NNNN-title.md`。
- ADR 采用背景、决定、理由、后果和替代关系结构。
- ADR 只增不删；新决策通过链接标记替代旧决策。

## 错误闭环

- 只记录影响交付、事实准确性、文件安全或重复发生的问题。
- 编号使用 `ERR-YYYYMMDD-NNN`，复发沿用原编号。
- 状态使用未定位、缓解中、已解决和已重开。
- 两次等价失败后停止盲试，固定复现条件并一次验证一个可证伪假设。
- 原始复现消失、定向验证和相关回归通过后才能标记已解决。

## 精简原则

- 新增 Skill 或 Agent 前，先判断现有规则、模板和检查脚本能否解决。
- 不建立与项目规模不相称的治理系统。
- 不把同一事实复制到多份文档；其他位置只保留链接和短摘要。
