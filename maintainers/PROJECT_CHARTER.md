# 项目宪章

本文件记录 PM-product-workflow 的长期使命、定位和明确边界。内容极少变更；修改属于高风险，须按维护政策通过 PR 加强审查并验证，由 Coding Agent 根据证据决定是否合并。

## 使命

为产品经理提供一套可追溯、可接续、可交付的工作流，围绕实际原型需求变化，澄清影响、复用既有框架迭代原型、按业务路径验收、同步事实和版本差异，并向相应接收方交接；开发实现反馈回流后继续迭代。

Codex 是首版参考实现，公开方法不绑定单一模型或工具。

## 定位

- 核心使用场景是产品经理在既有桌面 Web 原型上进行需求开发迭代；响应式适配作为补充，按任务检查相关视口。
- 主要服务政务与复杂 B 端产品经理，开发者可以协作使用。
- 核心机制可以迁移，默认维护 `gov-enterprise-cn` Profile。
- 产品交付形态是方法、模板、Skill、Profile 和完全虚构的辅助教学案例；仓库自管理脚本不作为产品能力。
- 教学案例帮助理解工作流，不代表使用者实际原型的质量，也不替代有范围的真实需求迭代。

## 核心原则

1. Repository is memory. Conversation is working context.
2. 事实必须有来源，并区分已确认需求、原型表现、已核对实现说明及其差异。
3. 按需读取上下文，不把全部历史塞进每次会话。
4. 改动同步规则，错误形成闭环，验证分层表达。
5. 优先完善现有流程，再增加 Skill、Agent 或治理文件。

## 明确不做

- 不公开或改名包装任何真实项目材料、代码、截图、数据和对话；可以吸收开发实现反馈，但不复制真实源码或业务内容公开。
- 不绑定前端框架、设计系统或 Coding Agent。
- 不建立自动语义裁决、全量对话同步或向量记忆库。
- 不提供生产接口、真实权限系统或真实后端。
- 首版不承诺 C 端、移动端和多设计体系的成熟预设。
- 不以扩展大型演示作为主线价值，也不以小演示推断真实原型迭代质量。
- 不在缺乏证据时承诺性能或成本改善比例。
- 不复制无明确许可的第三方规范、代码和资产。

## v0.1 成功标准

不了解作者历史对话的新使用者仅凭公开仓库即可：

1. 说明明确的需求变更并评估影响，在既有桌面原型上完成可审阅迭代；响应式检查按受影响范围补充。
2. 按证据记录事实，区分已确认需求、原型行为、已核对实现说明及版本差异，并注明来源。
3. 在新会话中从现有记录正确接续，避免重复已否定方案。
4. 按接收方获得适用成果；v0.1 仍要求对交付物实际进行浏览器离线预览和独立验包。

上述完整主流程仍须由独立非开发产品经理实际试用。AI、浏览器自动化、工程演练或非目标用户反馈不能替代该人测；小页面演示只作为辅助工程观察，不构成主线产品价值验收。正式 Release 仍须另行明确授权。
