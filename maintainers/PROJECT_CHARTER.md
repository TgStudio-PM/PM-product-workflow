# 项目宪章

本文件记录 PM-product-workflow 的长期使命、定位和明确边界。修改按仓库维护政策通过 PR 加强审查并验证。

## 使命

为政务与复杂 B 端产品经理提供一套可追溯、可接续、可交付的原型开发与持续迭代工作流。围绕实际需求变化，分析影响、复用或建立原型代码、按业务路径验收，并同步必要事实和版本差异；按接收方交接，吸收开发反馈后继续迭代。

Coding Agent 与开发者可协作参与实现。Codex 是已验证工具之一，公开方法不绑定单一模型或工具。

## 定位

- 主线是代码成果与需求迭代，面向桌面 Web 原型；响应式检查按项目需要补充。
- 首要服务政务与复杂 B 端产品经理，开发者可协作。
- 既有原型优先复用项目已有技术栈、设计约束、组件和结构；也可从明确需求建立初始原型。工作流不交付通用应用脚手架。
- 事实模板、会话接续和按需交付是原型迭代的支撑能力，不替代原型开发本身。
- 默认维护可选 `gov-enterprise-cn` Profile；项目规则及适用平台规范优先。

## 核心原则

1. Repository is memory. Conversation is working context.
2. 区分有来源的已确认需求、原型表现、已核对实现和待确认差异。
3. 按需读取上下文，复用已有项目事实和代码。
4. 需求变化落实为可评审的原型改动，并按业务路径验收。
5. 错误形成闭环，验证层次据实表达；优先完善现有方法、模板和 Skills。

## 明确不做

- 不公开真实项目材料、代码、截图、数据、内部规则或对话，也不通过更名包装真实内容。
- 不绑定前端框架、设计系统或 Coding Agent。
- 不提供通用应用脚手架、生产接口、真实权限系统或真实后端。
- 不建立自动语义裁决、全量对话同步或向量记忆库。
- 不以公开演示应用或展示站作为核心产品，也不以演示内容推断使用者原型质量。
- 不在缺乏证据时承诺性能或成本改善比例。
- 不复制无明确许可的第三方规范、代码和资产。

## v0.1 成功标准

独立非开发产品经理在其有权访问的实际原型项目中，能够：

1. 从明确需求分析影响并完成可评审的原型代码改动。
2. 按来源同步需求、原型表现、实现说明和版本差异。
3. 需要续作时在新会话中依据现有记录接续，避免重复已否定方案。
4. 按实际接收方提供所需材料，并如实记录验证范围。

完整主流程仍待独立非开发产品经理实际试用；既有演示、AI 静态分析、工程演练或非目标用户反馈不计为通过。离线验收仅在具体交付要求离线使用时，检查目标环境入口和核心路径并独立验包。历史 Win2K/125% 等演示专属检查未完成，不标记为已通过，也不再作为当前全局门槛。正式 Release 仍须另行明确授权。
