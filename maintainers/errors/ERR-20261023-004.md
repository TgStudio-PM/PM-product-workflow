# ERR-20261023-004：交付 ZIP README 指向包内不存在的验包脚本

- 状态：已解决
- 日期：2026-10-23
- 范围：三类虚构交付 ZIP 的自动 README；Issue #71

## 现象与复现

已生成的交付 ZIP 的 `README.md` 末尾包含 `python package.py --verify <archive.zip>`，但白名单包内没有 `package.py`。接收者照该说明在解压目录运行会找不到脚本。README 也没有按静态预览、前端源码、后端需求材料分别说明查看入口。

错误特征：ZIP 中声明的内容与其使用说明不匹配，独立验包命令隐含了包内脚本存在。复核使用仓库原创虚构 Profile 和材料，没有读取或打包真实项目内容。

## 影响与根因

接收者无法依据包内说明直接找到正确的查看或使用入口，并可能在错误目录尝试运行未交付的脚本。根因是 `_readme` 统一追加固定命令，没有区分三类包用途，也没有说明验包脚本属于仓库且默认不随 ZIP 提供。另一个通用性风险是 frontend-source schema 不要求 `package.json`，所以不能对所有前端源码包假定 Node.js/npm 项目。

## 尝试及结果

- 解开生成的前端源码 ZIP，确认其 README 含有失效命令，归档文件清单不含 `package.py`。
- 调整 README 生成逻辑，按交付类型给出查看/使用入口；前端包仅在实际包含 `docs/ADD_PAGE.md` 时引用该指南。
- 将独立验包命令改为带有仓库路径和 ZIP 路径占位符的外部脚本调用，并明确脚本默认不随 ZIP 提供。
- 只有归档清单包含 `package.json` 时，才提示在其所在目录阅读项目说明并处理依赖/脚本；否则引导接收者先阅读声明入口和实际包内说明，不假定 Node.js 或 npm。

## 最终修复、验证与预防

以三种交付类型的定向测试确认 README 包含对应入口、不再给出包内 `package.py` 命令，并声明外部脚本来源；另测有/无 `package.json` 和未包含/包含新增页面指南时的前端 README。三类虚构 ZIP 均重新生成并通过独立验包。浏览器验收、前端工程验收和产品验收不由 README 文案测试证明，应按具体接收场景执行并单独记录。

以后修改自动生成的交付说明时，应以实际 ZIP 文件清单验证所引用的路径和工具是否存在；不得把结构或哈希检查描述为浏览器、工程或产品验收。

证据：[Issue #71](https://github.com/TgStudio-PM/PM-product-workflow/issues/71)、打包器定向测试与三类虚构 ZIP 的重新生成记录。
