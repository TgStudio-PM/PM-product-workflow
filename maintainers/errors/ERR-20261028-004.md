# ERR-20261028-004：窄屏状态提示挤压原生案例标题

- 状态：已解决（限修复后 `static-preview` 包 Chrome、Edge HTTP 验收）
- 日期：2026-10-28
- 范围：[Issue #140](https://github.com/TgStudio-PM/PM-product-workflow/issues/140)；虚构材料申报原生页面小屏提示布局

## 现象与复现

基线 `94d70d9` 的原生 `static-preview` 独立静态预览包在 Chrome 155.0.8059.86 和 Edge 155.0.4283.62 的本地 HTTP、390×844/DSF 1 视口中均可复现：恢复无效“已提交”记录后，更正保存成功提示的 `scrollWidth` 为 452px；控制性触发写入失败提示的 `scrollWidth` 为 464px；容器 `clientWidth` 为 390px。长提示与标题同排，导致标题被挤压。

无效记录状态本身仍恢复为可编辑草稿。成功更正本地记录后刷新，草稿状态稳定。写入失败用例仅通过对专用 key 控制性地令 `Storage.prototype.setItem` 抛错，不代表自然环境中的存储故障。该状态逻辑与 ERR-20261026-007 所述状态误锁定问题不是同一缺陷。

修复前基线 `static-preview` ZIP SHA-256：`6AED132368C7FAC7F097100472DCB1F522A448C4704BEBCEB9F89DA333311F6C`。独立验包、Node 7 项状态恢复测试与 `node --check examples/material-submission/app.js` 通过。完整基线记录仅用于区分此次布局问题与历史状态修复。

## 错误特征、影响与根因状态

错误特征：CSS 在 760px 及以下仍让 `.draft-indicator` 保持 `nowrap` 并与标题并排；长成功/失败提示没有空间换行，挤压标题。根因由布局规则确认。

影响限于手机窄屏的状态提示与标题可读性；不改变草稿更正、提交状态、材料计数或业务规则。

## 修复与验证

修复源码提交：`0f4653d2c0873a1f7b2e37c4bfd30aba1d77cbcd`。仅修改 CSS/HTML：长提示允许完整换行，手机标题、提示和材料计数改为上下排；移除固定材料卡高度以减少字体放大时的裁切风险。同步用户指定的政务蓝偏好：主色 `#1d63b8`、hover `#174f93`、辅助文字至少 12px、常用文字 14px、按钮高 40px、宽屏容器最大 1600px。HTML 只增加空 favicon。JS、业务文案、BR 与材料规则未改。首次候选的 Chrome、Edge HTTP 复验各出现一次 `/favicon.ico` 404 和一次 console error，其余交互均通过；这是当前静态预览入口的伴随请求问题，关联 [ERR-20261028-003](ERR-20261028-003.md)，不代表 Vue 回归。

机器验证：Node 状态恢复回归 7 项、`node --check examples/material-submission/app.js` 和差异检查通过。主线仓库治理测试 16/16 通过，其中包含三类虚构 Profile 的独立构建与验包。新 `static-preview` ZIP 已生成并独立验包通过，共 6 项：README、app、index、styles、manifest 和 SHA 文件；无新增运行资源。候选 ZIP SHA-256：`4A11A68171805F08BE8C388019B170B8EBC9B3E3ECEFA626E1807C10678CD8B8`。
