# ERR-20261023-003：交付包内相对链接目标缺失

- 状态：已解决（2026-10-29 第三次复发已复验）
- 日期：2026-10-23
- 范围：虚构 Vue 原型工程的前端和后端需求包及通用交付验包；原 Issue #69，复发记录见 Issue #97、Issue #99

## 复发记录（2026-10-24）

Issue #97 的新页面指南再次引用源码包根目录之外的 `templates/optional/API_HANDOFF.md`。按官方 `frontend-source` Profile 打包复现，返回 `MARKDOWN-02 relative link escapes bundle root: docs/ADD_PAGE.md:19`，退出码 2，未生成 ZIP。`docs/BACKEND_HANDOFF.md` 存在同类包外引用。原问题在 #69 中已解决，但源码包新增文档时没有把链接目标纳入交付清单审查，因此同类交付故障复发；原错误编号重开。

同时，`page:new` 只创建页面文件和路由注册项，没有创建模块事实文件；指南未清楚说明如何从模块模板建立 `src/modules/<module>/facts/module/`，使页面规则索引无法按预期落到权威事实源。

## 现象与复现

旧前端源码 ZIP 能通过 `package.py --verify`，但包内 `docs/ADD_PAGE.md` 的“新增页面人测卡”链接指向 `docs/ADD_PAGE_TRIAL.md`，该文件没有进入 ZIP。独立审计三类虚构包的 Markdown 相对链接：静态预览 0 处断链、前端源码 1 处断链、后端需求 0 处断链。没有读取或打包真实项目材料。

错误特征：清单和 SHA-256 均有效，接收者解包后仍无法打开被交付文档引用的本地文件。

## 影响与根因

前端源码接收者沿新增页面指南无法打开人测卡，交付材料不完整。直接原因是 `frontend-source.json` 白名单未包含该文件；检查缺口是打包器只对静态预览的 HTML/CSS 做常见本地资源检查，没有审计包内 Markdown 相对链接。

## 尝试及结果

- 固定旧 ZIP 后，旧验包器返回成功；独立包内链接扫描确认一处缺失。
- 在 Profile 的 `include` 和 `required` 中补入人测卡；在生成包及独立验包时检查常见 Markdown 行内相对链接。
- 新版验包器拒绝旧 ZIP，报告 `MARKDOWN-01` 与引用文件行号；重新生成的三类虚构包均通过新版独立验包，独立链接扫描发现 0 处断链。

## 原修复、验证与预防

打包器 30 项测试通过、1 项因本机 Windows 符号链接创建不可用而跳过；治理测试 11 项通过。新增定向测试覆盖有效链接、缺失目标、越出包根目录以及独立验包的断链拒绝。公开内容扫描、仓库 Markdown 链接和差异检查通过；GitHub CI 以关联 PR 为准。

以后改变交付白名单时，应核对包内文档的相对引用，并用独立验包检查实际 ZIP。自动检查仅覆盖常见行内 Markdown 链接，不等同于完整 Markdown 解析、目标浏览器运行或交付对象的产品验收。

原修复证据：[Issue #69](https://github.com/TgStudio-PM/PM-product-workflow/issues/69)、关联 PR 差异与 CI、仓库外本机忽略目录中的三包审计记录。

## 第三次复发记录（2026-10-29）

- **时间：**2026-10-29 17:55:48 +08:00。
- **范围：**PR #143 对 starter 人测卡和 README 的文档修改；官方 `frontend-source` Profile 的治理回归。
- **现象与复现：**`python -m unittest discover -s maintainers/tests -v` 实际运行 16 项，其中 frontend-source 子场景失败。原始错误为 `MARKDOWN-02 relative link escapes bundle root: docs/ADD_PAGE_TRIAL.md:5`。触发行是人测卡新增 `../../../docs/product/PROTOTYPE_ITERATION.md` 包外相对链接；starter README 也指向包外在线指南。
- **错误特征：**单仓库 Markdown 相对链接可解析，但相对路径越过独立交付包根目录；源码包审计拒绝该交付文档。
- **影响：**frontend-source 包不能通过治理验包；按白名单独立获取 starter 的接收者也无法从本地包内打开该主指南。错误仅涉及文档链接，不改变 starter 代码或离线运行资源。
- **根因：**修改分发文档时只检查了仓库内相对链接，没有按独立交付包根目录审查新增链接。
- **有效修复方案：**两处文档链接改为明确标注“在线”的 GitHub 工作流指南 URL；指南作为可选背景，不进入离线包依赖链。不复制指南进 starter、不扩大 Profile、不放宽扫描器。
- **验证状态：**修复后本地 `python -m unittest discover -s maintainers/tests -v` 16 项全部通过（31.140 秒），包含三类官方 Profile 实际构建及独立验包；原 frontend-source 失败子场景不再失败。公开内容扫描、全仓 Markdown 链接与差异检查通过，故关闭本次复发。本轮未做浏览器或目标 PM 人测；最新提交的 CI 另以 PR 为准。关联首次 CI 失败证据：[GitHub Actions run 40853138056](https://github.com/TgStudio-PM/PM-product-workflow/actions/runs/40853138056)。
- **预防规则：**修改分发文档链接时，除仓库链接检查外，必须核对目标相对包根的位置，并运行既有静态预览、frontend-source、backend-requirements 三类包回归；不得以仓库内链接存在代替包内可达性。
