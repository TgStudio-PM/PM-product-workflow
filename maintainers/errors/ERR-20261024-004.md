# ERR-20261024-004：静态交付审计跳过可执行 data URI

- 状态：已解决（静态审计范围）
- 日期：2026-10-24
- 范围：通用静态预览交付打包与独立验包；Issue #81

## 现象与复现

旧版 `_resolve_reference` 对所有 `data:` 引用直接返回。将虚构 HTML `<script src="data:text/javascript,fetch(1)"></script>` 交给 `_audit_static`，旧版没有报告，返回被接受。复现不执行 HTML 或脚本，只检查审计器返回值。

错误特征：可执行或可导入资源藏在 HTML/CSS `data:` 引用中，扫描器既不解析其内容，也不报告拒绝；其内的 API 字样不会经过普通 JavaScript 文件扫描。

## 影响与根因

静态预览打包和独立验包可能忽略脚本、内嵌文档或样式导入上下文中的内容，导致静态审计结果不完整。根因是资源解析将所有 `data:` scheme 统一当作可忽略的内嵌资源，没有依据 HTML/CSS 使用上下文区分可执行/可导入引用与图片等非执行引用。

## 尝试及结果

- 直接复现确认旧 `_audit_static` 接受 `script src=data:text/javascript`；未运行、未打开该内容。
- 将修复范围锁定为脚本、iframe/srcdoc、object/embed、HTML 样式表及 preload/import 链接和 CSS `@import` 的 `data:` 引用；普通图片用途保持兼容。
- 在正向测试中同时使用虚构 PNG `data:` 图片作为 HTML 图片与 CSS 背景，构建和独立验包通过。

## 最终修复、验证与预防

HTML 解析器现在记录可执行/可导入上下文中的 `data:` 引用并拒绝；CSS `@import data:` 同样明确拒绝。普通图片资源仍交给原资源解析逻辑。拒绝规则同时用于打包与独立 ZIP 验包。静态预览使用说明已更新，并继续说明自动检查是启发式扫描，不能证明浏览器完全离线。

`python -m unittest discover -s .agents/skills/pm-prototype-packager/tests -p 'test_*.py' -v`：35 项通过，1 项因当前 Windows 环境不支持符号链接创建而跳过。定向覆盖原始脚本 URI、iframe 文档、srcdoc、object、embed、样式表 link、modulepreload、CSS `@import`、图片兼容和重签名 ZIP 独立验包拒绝。三类实际 Profile 打包/验包、公开扫描、仓库链接检查和 CI 结果记录在关联 PR。

预防规则：修改静态资源审计时，分别检查 HTML 属性和 CSS 导入语境；同时测试打包阶段与独立 ZIP 验包，加入可保留非执行图片的正例。该修复只封堵已覆盖的可执行/可导入 `data:` 上下文，不证明任意 JavaScript 或其他动态资源不会联网；交付说明须保留此限制。

证据：[Issue #81](https://github.com/TgStudio-PM/PM-product-workflow/issues/81)、相关定向测试、静态代码审计复现。
