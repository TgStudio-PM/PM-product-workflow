# ERR-20261028-001：未知 Hash 地址静默回退概览页

- 状态：已解决（Issue #136 与 #172 定向及浏览器验证完成；最终 CI 待最终 PR 提交）
- 日期：2026-10-28
- 范围：[Issue #136](https://github.com/TgStudio-PM/PM-product-workflow/issues/136)；可选 Vue starter 导航

## 现象与复现

打开 `/#/not-registered` 或 `/#/material-submission/apply?id=demo-001`，页面均静默显示原型概览，而不是反馈路由未登记或展示已登记页面。

错误特征：`pathFromLocation()` 将 `#` 后的完整字符串与注册表 path 精确比较；未命中时返回 `pageRegistry[0]`。因此未知地址及带 query 的已登记地址都被误导至首页。

## 影响与根因状态

根因已定位为 Hash 解析与未命中处理：旧逻辑未拆分 path 和 query，并以概览页作为未知路由的静默默认值。影响评审、演示和交接中按地址定位页面的可靠性；不是真实业务事故，也不代表生产路由或权限行为。

## 尝试及结果

1. 将 Hash 解析收敛为 path/query 识别；未登记地址显示明确的“页面未登记”反馈和返回入口。错误页不显示角色或表单内容，且从地址参数不创建页面节点。
2. 为已登记当前项补充 `aria-current`，并保留已有静态页面注册与离线预览结构。
3. 首轮预览构建负例测试遇到 TypeScript `TS2322`；将 ref 显式声明为 `ref<string>` 后，相关回归通过。这里只记录实现过程，不推断更深层根因。
4. 后续发现静态注册 path 若含 `?` 会与运行时 path/query 拆分产生不一致。注册表解析器现拒绝含 `?` 的 path；独立验包与直接构建负例均拒绝，`dist` 逐文件快照及 SHA-256 未变化。

## 修复、验证与预防

机器验证：`npm run test:preview-verify` 最终 43/43 通过，其中覆盖 7 项 Hash helper/parser 用例及原预览用例、静态 path 守卫负例；`npm run preview:pack` 通过。未知地址、带 query 的登记地址和含 query 的登记定义均纳入验证。

产品验收：Chrome 155.0.8059.86 的本机 HTTP 环境在 1280×800 和 390×844 视口完成空 Hash、正常路由、参数路由、未知路由、未知 query、返回、Hashchange、前进/后退及草稿冒烟。无 console error 或 page error；长地址在 390 视口无横向溢出，未产生注入节点。该结果不代表 `file://` 验收、独立非开发产品经理人测或正式发布验收。

预防要求：解析 Hash 时分清 path 和 query；未知地址必须有明确反馈，不静默伪装为首页。静态注册表的路由约束须与运行时解析、AST 读取、构建和独立验包保持一致，并分别验证正常地址与非法登记值。

证据：[Issue #136](https://github.com/TgStudio-PM/PM-product-workflow/issues/136)、[ADR 0003](../decisions/0003-prototype-navigation-scope.md)、`starters/vue-prototype/src/app/router.ts`、`starters/vue-prototype/src/app/hash-location.ts`、`starters/vue-prototype/scripts/page-registry.mjs`、`starters/vue-prototype/tests/hash-location.test.mjs`、`starters/vue-prototype/tests/verify-preview.test.mjs`。

修前使用 Chrome `155.0.8059.86` 和 Edge `156.0.4314.58`，在 `file://`、1440×900、DSF 1 环境检查：四个中文或空格目标路径的菜单/带 id 直达/刷新均复现 404；两个 ASCII 对照正常，console、page error、requestFailed 和 HTTP 错误计数均为 0。该记录是缺陷复现，不是修后浏览器验收。更早的临时夹具曾因误加逗号被 TypeScript 类型检查拒绝；这是夹具问题，不归类为产品缺陷，原记录保留。

### 锁定修复与当前结果

运行时仅在原始登记值或其平台浏览器 fragment 序列化值上精确匹配；命中时返回登记原值。未知编码路径、大小写和斜杠形式不做通用归一化，原 query 拆分及空 Hash 默认入口保持不变。注册表仍保留原始静态字符串及 query/重复原值校验，并在原值唯一后拒绝不同登记值序列化成同一浏览器地址；构建和独立验包共享此检查，且须在产物写入前拒绝。
