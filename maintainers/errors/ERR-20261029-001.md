# ERR-20261029-001：接续演练输入基线不一致

- 状态：已解决（两种入口的独立源文本复核通过）
- 日期：2026-10-29
- 范围： [Issue #150](https://github.com/TgStudio-PM/PM-product-workflow/issues/150) 原创静态入口接续演练；未涉及真实项目资料或产品主线源码。

## 原始现象与只读复现

- 初始任务完成页面与模块 `CURRENT.md` 更新后，项目背景仍称处于输入准备、待处理任务未执行，并要求不得提前执行。
- 后续 fork-none 只读接续者核对项目背景、模块事实和页面，发现状态冲突并请求澄清；未重复执行任务。
- 现有项目把背景文件放在 `context/`，其中路径说明以“本文件同目录项目根”为参照；入口补充说明则以项目根为参照，模块清单未注明路径基准。

## 错误特征与影响

- 文件路径可达，但项目背景、模块状态与实际页面版本不一致；加载路径成功不能视为事实一致性验证通过。
- 接续者可能重复执行、误报待办，或在冲突未澄清时暂停；本次只读接续没有重复修改。

## 根因

- 演练输入将“准备阶段、尚未执行、不得提前执行”留在项目背景，同时把项目背景锁定为接续者只读，未按页面和模块事实同步当前状态。
- 模块清单没有声明“事实文件目录”和“入口”的相对路径基准；已有项目的背景和登记表位于 `context/` 而非项目根，放大了路径歧义。

## 尝试与修复

- 初次任务源文本已完成；复核指出背景与模块事实冲突后，保留原输入和证据，不把初次完成视为最终接续验收。
- 已将项目背景改为稳定范围与任务索引，具体进度由模块 `CURRENT.md` 记录，并明确模块清单路径相对项目根。关联记录 [ERR-20260908-001](ERR-20260908-001.md)，其记录的是仓库 PR 旧基线问题。
- 公开模板与两个演练登记已补充路径基准；四份初始事实副本 SHA-256 均匹配原基线。主线独立核对原输入保留、现有入口原文字节前缀和全新入口与最终模板一致。

## 验证与预防

- 修正后另一个无历史上下文 Agent 只读核对两条根入口，确认背景、模块状态、路径与源码一致，无明确待办且不重复任务；原始冲突未再出现。主线核对证据，公开扫描、链接及差异检查通过，因此关闭此源文本一致性问题。未运行浏览器、产品人测或生产验证；后续 CI 另以 PR 最终提交为准。
- 证据索引：`.codex-local/ACTIVE_PROJECT_ENTRY_TRIAL.txt` 指向的仓库外 `evidence/`；不复制原始日志或私有资料。
- 后续演练先核对项目背景、模块当前状态、页面与任务边界；登记表必须明确路径参照。不得仅以路径可达或任务文本已完成判定接续通过。
