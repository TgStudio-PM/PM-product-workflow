# ERR-20261112-003：必需文件缺失前仍读取全部白名单载荷

- 日期：2026-11-12
- 状态：已解决（限声明路径缺失的无效载荷读取及定向工程回归）
- 范围：[Issue #206](https://github.com/TgStudio-PM/PM-product-workflow/issues/206)，产品打包器的源文件收集阶段

## 现象、复现与影响

在完整有效的前端源码 Profile 中，白名单内声明一个实际缺失的必需文件，并保留八个各 1 MiB 的资源及一个入口。构建先读取九份载荷共 8,388,626 字节，最后才报告原有 `SOURCE-05` 缺失路径；没有生成 ZIP 或输出目录。

这是失败路径的无效读取，不是误接收缺文件包。大目录重试时会重复做这部分工作；本次没有测量真实工程总耗时或 Token 改善比例。

## 根因与修正

根因已定位：`_collect_files` 在遍历白名单时直接读取内容，必需文件、入口与页面的齐全性检查发生在读取之后。

第一版候选先枚举完整路径集合再逐文件复核读取，虽然避免失败载荷读取，但原创有效输入的成本检查发现，逐文件重查显著增加正常封包开销，因此未采用该实现。

收窄后的候选只提前检查声明的必需文件、入口和页面是否被白名单覆盖且实际存在，然后沿用原有文件收集及校验。正常输入仍每份载荷读取一次，白名单、重复/保留路径检查、缺失路径诊断、`SOURCE-04` 读取失败和最终独立验包保留。多个错误并存时，声明路径的问题会先于内容读取错误报告。

## 验证与预防

原始隔离输入、基线脚本和未采用候选的成本记录保存在本机，用于核对错误文本、载荷读取数、无产物状态及三种正常交付的包内内容与元数据。回归覆盖缺失的必需文件/入口/页面、正常单次读取、读取失败及既有路径校验；同时检查正常封包成本，不从单次计时承诺性能比例。

## 原始复验与关闭范围

相同原始缺文件输入在收窄后的实现中载荷读取为零，保留完全相同的 `SOURCE-05` 文本，没有 ZIP 或输出目录。静态预览、前端源码、后端需求三种正常包的成员内容及元数据均与基线逐字节一致，并可由原验包器独立验过。

本机打包回归 66 项，63 项通过、3 项因 Windows 符号链接创建权限跳过；治理及最终 GitHub CI 结果以对应 PR 为准。新增回归检查缺失或未纳入白名单的声明路径不读载荷，正常每文件读取一次，读取失败仍报 `SOURCE-04`。

原创 200 文件正常封包的交替成本检查未再出现第一版逐文件复核造成的明显开销。该检查只用于剔除候选回退，不代表真实工程的耗时或成本改善。问题关闭范围不包括文件在运行中变化的所有竞争情况，也不改变原验包和业务验收范围。

路径完整性可在读内容前判断时，先完成该检查；不为此增加每次打包的人工步骤、公共参数或跨任务缓存。工程验证不代替实际接收环境验收。
