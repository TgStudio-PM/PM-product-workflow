# ERR-20261026-002：facts:new 未拦截悬空链接和输出路径符号链接

- 状态：已解决（候选代码已修复；Linux CI 的符号链接运行用例通过）
- 日期：2026-10-26
- 范围：Issue #113 的未合并 Vue starter `facts:new` 候选；不是已合并 `main` 的回归

## 现象与复现

PR 前检查发现候选脚本以 `access()` 判断 `src/modules/<module>/facts/module/` 是否存在。对悬空符号链接，`access()` 返回 `ENOENT`，脚本会把目标当作不存在。另当 `src/modules/<module>/facts/` 等输出父路径已有目录符号链接时，递归 `mkdir` 与在其下创建临时目录可能沿链接写入工程根目录之外。

错误特征：目标检查忽略悬空链接；写入前未逐级检查模板路径及输出路径的符号链接。复现方式是在链接权限可用的系统中，将事实目标设为指向缺失路径的悬空链接，或将 `module-template/facts/` / `src/modules/<module>/facts/` 替换为指向工程外部目录的目录链接，再执行 `npm run facts:new -- demo-help`。

## 影响与根因状态

根因已定位：`access()` 跟随链接目标，不能识别悬空链接；脚本未对模板路径和输出父路径逐段执行 `lstat()`。若按候选实现运行，目标节点可能被误判，写入也可能经父路径链接落到工程目录之外。该缺陷发现于 PR 前的候选分支，没有证据表明它进入 `main` 或已发布包。

## 尝试及结果

- 新增悬空目标、模板目录链接和输出父目录链接三类测试。
- 当前 Windows 环境创建目录符号链接返回 `EPERM`；三项测试按要求明确标记为跳过，不能据此声称符号链接运行用例已通过。
- 实现改为用 `lstat()` 识别所有现存节点，并在模板路径、目标路径和输出父路径上逐级拒绝符号链接；目标存在性在初始检查和最终 rename 前复核。创建输出父目录后及写入临时目录期间再次检查路径。

## 修复、验证与预防

候选 `create-facts.mjs` 已加入逐级符号链接检查及悬空链接可见的目标存在性检查。`create-facts.test.mjs` 保留普通复制、拒绝覆盖、非法标识和缺模板回归，并新增上述链接用例；Windows 因权限不足时仅跳过链接用例。

GitHub Linux CI [run 40263168370](https://github.com/TgStudio-PM/PM-product-workflow/actions/runs/40263168370) 实际运行 `npm run test:facts-new`：7 项通过、0 项失败、0 项跳过。三类符号链接用例均返回预期拒绝，原始复现路径不再误判；同一 CI 中原 `page:new` 回归、类型检查、离线预览、治理、公开扫描和 Markdown 链接步骤通过。Windows 本机仍因 `EPERM` 跳过 3 项链接用例，不把 Windows 跳过记为通过。

预防规则：任何基于路径写入的脚手架都应使用 `lstat()` 检查目标节点，并在创建输出前逐级检查模板与输出路径已有组件；Windows 跳过链接用例必须如实记录，不能代替支持链接环境中的验证。

证据：Issue #113；PR 前候选源码 `starters/vue-prototype/scripts/create-facts.mjs`；定向测试 `starters/vue-prototype/tests/create-facts.test.mjs`；当前 Windows 环境创建目录链接返回 `EPERM`。
