# ERR-20261028-002：浏览器截图视口证据被后续截图覆盖

- 状态：已解决（限 Issue #140 在独立目录中重新采集并保护旧证据）
- 日期：2026-10-28
- 范围：[Issue #136](https://github.com/TgStudio-PM/PM-product-workflow/issues/136)；自动化浏览器验收截图与记录

## 现象与复现

验收循环将不同视口截图写入同一文件名 `unknown-route-1280x800.png`。后一次 390 视口截图覆盖前一次内容，导致文件名标注 1280×800，实际 PNG 尺寸为 488×1075。该文件仍保留，但不能作为 1280×800 验收证据。

错误特征：截图标签或文件名与图像实际像素尺寸不符；仅看名字无法发现覆盖。

## 影响与根因状态

根因已定位为截图循环使用固定输出文件名，视口之间发生覆盖。影响验收记录的证据准确性，不是产品运行缺陷，也不改变导航功能结论。

## 尝试及结果

1. 保留原 `unknown-route-1280x800.png` 文件供历史追溯，但撤销其作为 1280×800 证据的用途；不以文件名推断实际视口。
2. 将截图操作拆为独立浏览器 context，输出文件名包含视口与设备像素比（DSF）；同步修正截图记录中的文件名和元数据。

## 修复、验证与预防

重新取得的 1280×800、DSF 1.25 截图实际为 1600×1000 PNG，且已由主线查看确认视口正确；390×844 截图实际为 488×1075 PNG，截图修正 JSON 记录与对应文件匹配。两者均使用整页截图，图像高度取决于文档高度，不能直接用视口高度乘 DSF 判断。修正后的证据按各自视口保存，没有互相覆盖。

预防要求：多视口验收使用独立浏览器 context 和包含视口/DSF 的唯一文件名；保存后核对 PNG 实际尺寸及验收记录，不单凭文件名认定视口。公开记录只列证据文件基名与可复核事实，不写本机绝对路径或原始日志。

证据：`unknown-route-1280x800.png`（已标记为无效的 1280×800 证据）；修正后的视口/DSF 截图及匹配的截图 JSON 记录；[Issue #136](https://github.com/TgStudio-PM/PM-product-workflow/issues/136)。

## Issue #140 截图证据复发

旧记录的截图归档问题在 Issue #140 浏览器复验中复发。QA 复用了保留旧闭包状态的 Node REPL；`shotDir` 仍指向上一轮临时目录，导致 Chrome、Edge 各自 1280 与 390 视口的四张初始截图被新截图覆盖。受影响文件基名为 `chrome-initial-draft-1280x800-dsf1-fullpage.png`、`chrome-initial-draft-390x844-dsf1-fullpage.png`、`edge-initial-draft-1280x800-dsf1-fullpage.png` 和 `edge-initial-draft-390x844-dsf1-fullpage.png`；文件在 2026-10-28 11:45:08–11:45:12 UTC 间被更新。它们不能再作为原始初始证据或新验收结果使用。保留现有文件供追溯，不覆盖、删除或据此声称复验完成。

根因已确认：复用 Node REPL 时，闭包持有旧输出目录；执行写入前未校验截图目标路径。QA 写入已停止。原 Chrome 桌面初始草稿图与恢复长提示反例图未受影响；基线与修复后 `static-preview` ZIP 均仍存在，且哈希复核未变，具体包哈希仅见 [ERR-20261028-004](ERR-20261028-004.md)。产品行为及布局复现证据仍有效。这是证据管理问题，不是案例业务缺陷。受影响图片原内容未恢复，不能将现有同名文件继续作为原始截图的证明。中断后生成的浏览器 JSON 记录不完整，不作为验收结果。

最终补采：从已验包复制到全新目录，以独立 Node 进程完成 Chrome、Edge HTTP 复验；8 张新截图使用唯一输出文件，实际视口/布局经主线抽查确认。52/52 项旧证据 SHA-256 均未变化，主线独立重算一致。首次被覆盖的四张截图保持原文件并继续撤销验收用途，哈希一致不表示其原始内容已恢复。中断后不完整 JSON 不作为验收结果。该错误限 Issue #140 的新证据采集与防覆盖闭环。

预防要求已复验：从已验包复制到唯一目录，用独立单次 Node 进程运行；写入前验证截图目标路径，保存后检查实际视口和布局；结束时复核旧证据哈希保护清单。浏览器矩阵及 HTTP 请求结果见 [ERR-20261028-004](ERR-20261028-004.md)。
