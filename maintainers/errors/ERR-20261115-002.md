# ERR-20261115-002：源文件读取失败未指出具体文件

- 日期：2026-11-15
- 状态：已解决（限源文件读取失败的相对路径诊断）
- 范围：[Issue #220](https://github.com/TgStudio-PM/PM-product-workflow/issues/220)，产品打包器的 SOURCE-04 诊断

## 现象、复现与影响

原创隔离输入含两份文档，在 Windows 对其中一份持有禁止共享读取的文件句柄。基线 CLI 报 SOURCE-04、exit 2，没有 ZIP 或输出目录；但未指出读取失败的文件，无法从报错直接定位白名单中的故障项。释放句柄后文件哈希未变。

读取失败本身是环境条件；本问题是诊断信息不足，增加重试前的查找成本，不是应让不可读文件通过封包。没有证明真实项目的全部失败都由占用引起。

## 根因与修正

根因已定位：收集阶段捕获 OSError 后仅返回固定通用文字，丢弃了当时已知的归档相对路径。

在现有错误码和文字前缀后补充 JSON 转义的 archive_name 及错误类型；不输出异常原文、绝对路径或文件内容。保留失败退出、读取与白名单约束，不自动重试，不增加参数或配置。

## 原始复验与关闭范围

同一原始 Windows 锁文件输入已能指出失败相对路径和 PermissionError，原 SOURCE-04 前缀及 exit 2 保持，未输出绝对路径；原文件哈希不变，没有 ZIP 或输出目录。释放锁后，CLI 正常封包和单独验包均 exit 0。

回归覆盖后一个文件读取失败、非 ASCII/空格文件名、PermissionError 与一般 OSError，以及不泄漏异常原文和绝对路径。原完整消息相等断言改为核对稳定前缀与必要定位信息。Windows 本机打包回归 70 项执行完成，三个符号链接子用例因权限跳过，其余执行结果通过；治理 16 项及链接、公开内容和 Skill 格式检查通过。

关闭范围仅为失败诊断可定位、原失败边界保留和本轮工程回归，不包括所有文件系统故障。最终 CI 和合并状态见对应 PR，原始输入与错误日志只保存在本机。工程结果不代表真实项目总耗时、Token 收益或独立 PM 试用。
