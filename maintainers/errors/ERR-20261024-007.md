# ERR-20261024-007：将已核对的页面现状误记为已确认业务规则

- 状态：已解决
- 日期：2026-10-24
- 范围：模块业务规则、当前状态与可选 API 对接模板；Issue #95

## 现象与复现

在完全虚构的隔离演练中，只核对到“页面当前显示一个字符串”，Agent 仍将该观察写成 `BUSINESS_RULES.md` 的 `BR-001 Confirmed（已确认）`，并添加“仅为原型现状”的备注。备注没有阻止观察被错误归类为已确认业务规则。该演练不涉及真实项目、数据或资料。

错误特征：把源码或页面作为实现证据，却将其当前表现提升为已确认产品规则；即使附带“原型现状”备注，规则表中的 Confirmed 状态仍会造成误读。API 模板中责任人、日期或验证结果留空时，也无法区分“未指定/未验证”与漏填。

## 影响与根因状态

使用者可能将当前原型表现误认为已确认的业务语义，进而影响后续设计或接口映射；API 对接记录也可能因空白单元格而被误解为已完成确认或验证。已定位的文档因素：旧模板虽指出源码只能证明当前实现，但 `CURRENT.md` 没有独立的当前实现栏位，规则表也缺少直接的放置提示；API 模板没有说明空白责任人与验证字段应如何表达。此结论只针对本次虚构演练的使用路径，不推断所有误分类都由同一因素造成。

## 尝试及结果

- 无效尝试：在虚构演练中的规则描述附加“仅为原型现状”备注；观察仍被录入 `BR-001 Confirmed`，未能消除分类错误。
- 有效尝试：在业务规则模板明确限定其记录范围，并将已核对实现引导至 `CURRENT.md`；增加产品指南对两类事实的简短区分；在 API 模板明确未指定责任人/日期及未执行验证时的填写值。

## 最终修复、验证与预防

在 `BUSINESS_RULES.md` 明确限制业务规则的来源和状态，给 `CURRENT.md` 增加“当前实现”栏位，产品指南区分已核对实现与已确认需求，并在 API 模板明确缺失责任人和验证的填写值。全新上下文的独立只读复做仅凭公开指引和模板，将“页面当前显示字符串”放入 `CURRENT.md`，没有生成 `Confirmed` 业务规则；将“服务端是否保存”保留在 `API_HANDOFF.md` 的待确认项，确认人写“未指定”、接口验证写“未验证”。随后在被忽略的隔离目录实际复制模板、创建虚构静态页并填写三份模块文档；主线重读页面源码和填写结果，确认引用文件存在且分类不变。首次只读分类没有读取旧演练、Issue 或本错误记录；本地 Markdown 链接、公开内容扫描、治理测试 11 项与差异检查通过。因此本次原始误分类在相同虚构场景下未再出现，错误状态改为“已解决”。这不等于浏览器验收、非开发产品经理人测或真实 API 联调。

预防规则：实现证据只能支持“当前实现”记录；只有产品负责人/业务责任人确认的业务规则才可标为已确认。对接模板中责任人、日期和验证结果不得以空白表达缺失状态。

证据：Issue #95；完全虚构隔离演练的任务描述与全新上下文独立只读复做；模板改动 `templates/module/BUSINESS_RULES.md`、`templates/module/CURRENT.md`、`templates/optional/API_HANDOFF.md` 和使用说明 `docs/product/README.md`。
