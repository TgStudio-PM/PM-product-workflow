# ERR-20261026-004：page:new 可经链接父路径写入工程外

- 状态：缓解中（本地目录链接定向用例通过；文件符号链接用例因 Windows 权限跳过，等待 Linux CI）
- 日期：2026-10-26
- 范围：Issue #118；可选 Vue starter 的 `page:new` 脚手架

## 现象与复现

外部隔离测试报告指出，受评基线的模块输出父目录或 `src/app` 通过目录链接指向工程外时，`page:new` 可能在工程外创建页面或修改注册表。源码核对显示：旧实现用 `path.resolve` 组装路径、用 `access()` 判断目标存在，然后执行目录创建、暂存写入与重命名，没有逐级检查路径链接。另有悬空目标链接被 `access()` 视为不存在的风险。

错误特征：页面模板、模块输出父路径、注册表父路径或目标节点包含链接时，脚手架仍可能沿路径执行读写。反例只允许在隔离的虚构临时工程中运行；不得用于真实项目。

## 影响与根因状态

根因已定位：词法路径位于工程内不等于实际文件操作仍在工程内；`access()` 跟随目标且无法识别悬空链接。旧实现没有在关键写入前复核路径组件。这个风险只涉及本地脚手架对调用者文件系统的操作；没有证据支持远程执行、生产数据损坏或真实项目曾发生同类事故。

## 尝试及结果

1. 参照同仓库 `facts:new` 已验证的局部模式，改用 `lstat()` 检查目标与路径组件；拒绝模板、输出及注册表路径中的符号链接，不引入共享框架或新依赖。
2. 在创建输出目录后、暂存写入期间和最终重命名前重复检查，保留正常新增页面、拒绝覆盖及注册表保护行为。
3. Windows 本地针对模块输出、模板及注册表目录链接的 3 项反例实际运行并通过，工程外现有内容保持不变；悬空文件链接创建返回 `EPERM`，用例明确跳过，不能作为该情形通过的证据。

## 修复、验证与预防

本地 `npm run test:page-new`：11 项通过、1 项因权限跳过；`npm run test:facts-new`：4 项通过、3 项因权限跳过；`npm run typecheck`、公开内容扫描、Markdown 链接检查、`git diff --check` 通过。仍需在支持文件链接的 Linux CI 中确认四项新增定向用例均实际运行且通过，再判断是否关闭本记录。

预防规则：本地脚手架写入前不能仅依赖字符串路径或 `access()` 判断；对已有路径组件和最终目标使用不跟随链接的检查，并用隔离工程验证工程外文件不变。系统无链接权限时标记跳过，另取支持环境验证。

证据：Issue #118；`starters/vue-prototype/scripts/create-page.mjs` 与 `tests/create-page.test.mjs`；相邻先例 [ERR-20261026-002](ERR-20261026-002.md)。
