# ERR-20261026-003：公开扫描漏检带引号凭据键

- 状态：已解决（本地定向复现、相关回归及 GitHub Linux CI 均通过）
- 日期：2026-10-26
- 范围：Issue #117；公开内容扫描器的 `SECRET_ASSIGNMENT` 规则

## 现象与复现

当前基线的扫描规则在凭据关键字后直接要求赋值分隔符。带引号的 JSON 或对象键在关键字与分隔符之间还有闭合引号，因此可能漏检。使用完全虚构的键值构造最小样例，修复前 `scan_text("sample.json", ...)` 返回空发现；既有未加引号赋值样例仍能检出。

错误特征：带引号键的凭据赋值未报告 `SECRET_ASSIGNMENT`。复现仅使用虚构字符串，没有读取或公开真实凭据。

## 影响与根因状态

根因已定位：原正则的关键字后只允许空白与 `:`/`=`，没有接受可选闭合引号。`.json` 属于待扫描文本类型，故扫描通过容易被误解为覆盖这种常见格式。尚无证据表明仓库曾包含真实凭据；本条只描述检查能力缺口。

## 尝试及结果

1. 先增加未加引号、单引号键、双引号键与跨行赋值的定向用例；修复前新增的带引号与跨行样例失败，固定了原问题。
2. 将规则限于原有凭据关键字，允许关键字外围的单/双引号与分隔符前后空白；未增加外部依赖或新的秘密类型。
3. 修复后，虚构 JSON 键的原始复现返回 `SECRET_ASSIGNMENT`，规则输出仍只包含编号、路径和行号，不回显匹配值。

预防规则：新增敏感扫描规则时，同时给出该格式的虚构正例和普通文本负例，并核对日志不回显内容。扫描只覆盖已列模式，不构成全量秘密发现；开源前仍需人工核对来源、组合可识别性与权属。
