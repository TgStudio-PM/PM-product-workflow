## 现象与复现

本机 Windows 工作副本的根目录 `LICENSE` 是现有 MIT 全文，CRLF 换行、1087 字节，SHA-256 `4ab308d60c59e51942b88286c37fb0be8a59591dd215917973954a20c1eff4d7`，版权行为 `Copyright (c) 2026 TG_Studio`。Git 中规范化的 LF 正文为 1066 字节，SHA-256 `786f0e55b0ce8cad1720a67ec977313b081546cce5f9125ff5c3d4ffe5e518ef`；两个副本规范化后的 Git 对象均与根 `LICENSE` 一致。下列本机候选保留 Windows 工作副本字节，不把不同换行的文件摘要混为一项。

只读检查确认现有 Vue 前端源码 ZIP（`3d7ade7…`）、Vue 静态 ZIP（`1ebcfefe…`）及原生静态 ZIP（`6bef0eff…`）均未包含该全文或 TG_Studio 原创归属。Vue 静态包的 `THIRD_PARTY_NOTICES.txt` 只涵盖 Vue 运行组件。后端需求包缺失情况依据 Profile 白名单确认，未将其表述为已检查的实际 ZIP。

复现方式：分别检查上述已固定归档的文件清单和内容；再查看三个示例 Profile 的 `include` 与 `required`，均未列出原创许可文件。未读取或打包真实项目材料。

## 根因与影响

Profile 白名单没有携带根 `LICENSE` 的副本，Vue starter 预览构建也没有复制或校验原创许可文件。接收方单独取得示例或 starter 时，无法从其交付内容确认本仓库复用内容所附的许可与归属。该问题不改变根许可，也不表示依赖许可已完整审计。

## 尝试及修复

- 只读核对 Issue #166 与指定的旧归档证据；未修改旧 ZIP 或既有候选。
- 在本仓库虚构案例和 Vue starter 中逐字节复制根 `LICENSE` 为 `UPSTREAM_LICENSE.txt`；不更改根许可或版权。
- 三个现有 Profile 的 `include` 和 `required` 均纳入该文件。
- Vue 构建在 Vite 清理输出前读取并拒绝缺失或空白输入；将正文写入独立预览文件，并纳入 README、manifest 与 SHA-256。专用验包逐字节比较预览文件和当前 starter 输入。
- 补充独立临时夹具回归，覆盖完整正文、缺失产物、摘要重签后的陈旧正文，以及缺失/空输入失败前保留旧预览。测试仅复制到临时目录；正式依赖目录保持只读。

## 预防规则

独立分发本仓库内容时，检查对应 Profile 的 `include` 和 `required` 是否同时保留上游许可文件；构建产物应与其源文件逐字节对照，并为缺失、空输入、缺失产物和摘要重签后的陈旧正文保留定向回归。上游许可说明不自动授权用户新增内容，也不构成私有材料公开许可、全依赖审计或法律结论。
