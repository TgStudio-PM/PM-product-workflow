# ERR-20260908-001：旧基线导致 PR 状态误判

- 状态：已解决
- 日期：2026-09-08
- 范围：仓库维护启动与当前状态

## 现象与复现

PR #3 已在远端合并，但仓库状态文档仍将其列为进行中；未刷新远端引用的旧工作副本也显示过期的 `main`。只读取旧工作副本和长期记忆时，会错误判断 PR 仍待确认。

错误特征：

- `CURRENT.md` 包含“PR #3 正在进行”或“PR #2 合并后状态”。
- 本地 `origin/main` 与 GitHub 当前 `main` 不一致。
- 关联 PR 的远端状态没有在开始任务时单独核对。

## 影响

维护者可能复用已合并分支、重复执行工作，或把已完成事项继续报告为阻塞，影响事实准确性和接力可靠性。

## 根因

1. 当前状态文档保存了短期 PR 审批状态，PR 合并后没有同步。
2. 启动流程只要求核对当前提交，没有明确要求获取远端状态并单独核对关联 PR。
3. 旧克隆和长期记忆被误当成当前事实。

## 尝试及结果

- 仅检查旧工作副本：失败，得到过期结论。
- 查询 GitHub PR 状态并重新克隆 `main`：成功，确认 PR #3 已合并。

## 最终修复

- 将短期 PR 状态留在 GitHub，`maintainers/CURRENT.md` 只记录稳定基线、里程碑和下一步。
- 在根 `AGENTS.md` 与 `maintainers/WORKFLOW.md` 中增加远端 `main`、关联 PR 和本地提交的独立核对。
- 明确不复用已合并分支，旧克隆和长期记忆只作线索。

## 验证与预防

- 从远端默认分支建立干净工作副本，并确认包含 PR #3 的合并提交。
- 后续接力测试必须先核对工作树、远端 `main` 和关联 PR，再读取当前状态。
- 若三者冲突，停止基于旧分支修改，先修正事实源。
