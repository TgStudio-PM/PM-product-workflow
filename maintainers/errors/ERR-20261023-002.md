# ERR-20261023-002：页面注册表字段重排导致离线清单错配

- 状态：已解决
- 日期：2026-10-23
- 范围：Tg Studio Vue 原型工程模板的离线预览构建与验包；Issue #67

## 现象与复现

在只读内存副本中，把虚构页面注册表第一项的 `title` 移到 `path` 前面，字段值和页面组件均不变。旧提取表达式得到 `/overview => 材料申报`，并漏掉第二页。这是合法的对象字段顺序；运行时注册表仍包含两页。复现没有修改仓库源码或真实项目材料。

错误特征：旧打包脚本和验包脚本使用相同的跨字段正则，可能把不同注册项的路径与标题拼在一起，造成生成和校验一起接受错误的 `PAGES.md` 与 manifest 页面清单。这里的直接证据是旧表达式的提取结果，不将其描述为已发生的浏览器页面故障。

## 影响与根因

新增页面的维护者调整字段顺序后，离线交付的路由数量与标题可能失真，静态审计也可能误报通过。根因是正则按文本跨越注册项匹配 `path` 和后续 `title`，没有把两个字段绑定在同一个对象中。

## 尝试及结果

- 固定第一项字段重排的只读复现，旧提取只返回一个错配结果。
- 将构建与验包共用的页面元数据读取改为 TypeScript AST，按单个注册项的字段名提取静态 `path`、`title`；缺失、动态或重复路由明确失败。
- 在隔离副本实际构建、验包并核对两页的 manifest 与 `PAGES.md`，增加动态标题的拒绝测试。

## 最终修复、验证与预防

字段重排的定向集成测试和动态标题负向测试通过；现有预览验包测试共 8 项通过。`npm run typecheck`、`npm run preview:pack`、`npm run preview:verify` 及仓库治理与打包测试通过。CI 和前端源码包独立解包验收以关联 PR 记录为准。

以后修改页面元数据提取时，应以注册项为边界并保留字段重排与非法输入的回归测试。前端源码包必须包含共享解析器；静态审计通过仍不等于目标浏览器的 `file://` 交互验收。

证据：[Issue #67](https://github.com/TgStudio-PM/PM-product-workflow/issues/67)、关联 PR 的差异和 CI、仓库内隔离集成测试。
