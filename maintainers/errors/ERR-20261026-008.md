# ERR-20261026-008：非字符串交付 kind 抛出未受控异常

- 状态：已解决（受控错误与包结构验证范围）
- 日期：2026-10-26
- 范围：Issue #129；通用打包器 Profile 加载与独立 ZIP manifest 验包

## 现象与复现

用完全虚构的临时 Profile 设置 `kind={}`，当前 `_load_profile` 抛出 `TypeError unhashable type: 'dict'`，没有返回既有 `PROFILE-05`。将本仓库虚构静态 ZIP 的 manifest 中 `kind` 改为对象，再调用独立 `verify`，同样得到未受控 `TypeError`，没有返回 `VERIFY-04`。反例均为本机临时文件，未进入仓库。

错误特征：JSON 允许对象/列表等非字符串值，但在检查三类合法交付类型前，代码直接对该值做集合成员判断。

## 影响与根因状态

根因已定位：Profile 与 ZIP manifest 的 `kind` 校验缺少字符串类型门禁；字典、列表等不可哈希值在集合成员判断处抛出 Python 异常。该问题影响错误提示与调用方对失败的处理，不代表畸形输入曾被接受或生成有效交付包，也不涉及浏览器运行或真实项目。

## 尝试及结果

1. 已分别固定 Profile 与独立验包的虚构反例；有效三类交付包仍须回归验证。
2. 在两处集合成员判断前加入字符串类型门禁，保持合法三类 `kind` 的既有分支；对象和列表分别返回既有 `PROFILE-05` 或 `VERIFY-04`。
3. 定向测试覆盖 Profile 加载与被修改的虚构 ZIP manifest 独立验包，均不再抛出 TypeError。

## 修复、验证与预防

`python -m unittest discover -s .agents/skills/pm-prototype-packager/tests -p 'test_*.py' -v`：47 项通过，1 项因 Windows 无法创建符号链接而跳过（与本次 kind 类型反例无关）。仓库治理测试 16 项通过，包含三类虚构 Profile 的实际构建和独立 ZIP 验包；公开扫描、Markdown 链接与 `git diff --check` 通过。GitHub CI 结果另见关联 PR，不能由本地结果预先代替。

预防要求：解析外部 JSON 字段时先核对类型，再执行依赖哈希/字符串方法的判断；同时测试构建入口与独立 ZIP 验包的非字符串反例，不扩大成通用 schema 框架。该检查只改善错误分类，不证明目标浏览器或产品验收。
