# ERR-20261115-001：输出目录创建失败导致 traceback

- 日期：2026-11-15
- 状态：已解决（限输出目录失败诊断及已存在父级文件冲突的无效读取）
- 范围：[Issue #218](https://github.com/TgStudio-PM/PM-product-workflow/issues/218)，产品打包器输出路径处理

## 现象、复现与影响

以完整有效的后端需求 Profile 和原创输入执行封包，输出父路径被一份既有普通文件占用。基线 CLI 返回 1 并输出 traceback；build 抛出 FileExistsError，此前已读取一份 Markdown 及 1 MiB 附件。既有文件未变、没有生成 ZIP。

这是打包失败诊断与无效读取问题，不是覆盖原件或误接收内容。重复相同命令不能解决目录冲突；未测真实工程总耗时或 Token 改善。

## 根因及修正

根因已定位：输出路径检查没有识别父级普通文件冲突；实际 mkdir 发生在载荷及内容审计后，并位于预期写入异常的转换范围之外。

修正在读取载荷前只读检查最近的已有父路径，冲突时返回 OUTPUT-01。实际创建目录仍在内容审计后执行，创建异常单独转换为 OUTPUT-01，避免误报为已有归档 OUTPUT-02。

不新增参数、配置、依赖或缓存，不改变源内容、白名单、不可覆盖及最终独立验包。不可访问目录或运行时状态变化仍可能在后续创建/写入阶段失败，早期检查不保证目录可写。

## 原始复验、回归与关闭范围

保留本机原始输入、基线 stderr 和读取记录；同一输入修正后返回 OUTPUT-01、CLI exit 2，无 traceback，源码载荷读取为零，既有文件字节不变且没有 ZIP。

定向回归覆盖直接/上级普通文件冲突、受控 PermissionError 及正常自动创建缺失目录；Windows 本机打包回归 69 项执行完成，3 个符号链接子用例因创建权限跳过，其余执行结果通过，需由 Linux CI 补核。治理 16 项通过，链接、公开内容和差异检查通过。

对同一正常输入，修正后包内成员、README、manifest 和摘要均与基线逐字节一致，新包通过基线及修正后两个独立验包器。受控权限异常只验证错误处理，不证明已在真实受限目录交付。关闭范围不包括所有输出竞争或磁盘异常；机器结果不等于目标项目运行、整体性能改善或独立 PM 试用。

最终 GitHub CI 及合并状态由对应 PR 记录承担，原始日志及候选 SHA256 留在本机。
