# ERR-20261024-003：并行验证清空共享预览目录导致测试误失败

- 状态：已解决
- 日期：2026-10-24
- 范围：Tg Studio Vue starter 的本地 PR #77 验证调度

## 现象与复现

在同一工作副本同时启动 `npm run test:preview-verify` 和 `npm run preview:pack`。旧预览测试会把工程的 `dist/preview` 复制到隔离夹具；打包命令会先清空并重建这个目录。并行运行中，测试的 manifest 篡改用例读取隔离夹具的 `manifest.json` 时出现 `ENOENT`，第一次测试结果为 8/9 通过。

错误特征：单个测试夹具缺文件；同次打包成功。停止并行、待打包结束后单独重跑测试，9/9 全部通过。

## 影响与根因

这次错误会使 PR 的验证结论失真，但没有修改受跟踪源码；本地 `dist/preview` 被打包命令正常重建且最终验包通过。根因是主线把共享 `dist/preview` 状态的两项验证误判为可并行执行；现有测试夹具在复制预览目录时依赖该目录保持稳定。它不是 Issue #77 修复代码的失败，也不能用第二次通过抹去第一次失败记录。

## 尝试、修复与验证

- 首次并行：`preview:pack` 成功，预览测试 8/9，通过用例以外出现 `ENOENT`。
- 固定验证顺序：待打包完成后，单独运行 `npm run test:preview-verify`，9/9 通过；没有为这次调度错误修改产品代码。
- 根因状态：已定位。定向复验和相关回归通过；若同类问题复发，沿用本编号重开。

## 预防规则与证据

同一 starter 工作副本上的预览构建和依赖 `dist/preview` 的测试必须串行运行；只有文件与状态互不共享的检查才可并行。PR 验证记录应保留首次失败与串行复验两个结果，不能只报告最终绿色结果。证据见 Issue #77 关联 PR 的验证说明和本地命令输出。
