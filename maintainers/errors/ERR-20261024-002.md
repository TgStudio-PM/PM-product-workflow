# ERR-20261024-002：离线预览打包未执行 Vue 类型检查

- 状态：已解决
- 日期：2026-10-24
- 范围：Tg Studio Vue 原型工程离线预览打包入口；Issue #77

## 现象与复现

在隔离 Vue starter 副本中，删除 `src/app/page-registry.ts` 某个页面注册项的 `component` 属性。`npm run typecheck` 会因 `App.vue` 访问缺失属性而以 TS2339 失败，但旧版 `npm run preview:pack` 仍构建并通过结构审计，退出码为 0；产物中的该页面无法渲染。

错误特征：类型检查单独失败，而标准离线打包命令绕过检查并报告成功。

## 影响与根因

新增页注册项不完整或存在其他 Vue/TypeScript 错误时，维护者可能把结构审计误认为可运行交付。根因是 `preview:pack` 只调用 Vite 构建与静态验包；Vite 会转译 TypeScript，但不会执行类型检查。

## 尝试及结果

- 隔离副本复现 `typecheck` 退出 2、`preview:pack` 退出 0。
- 将 `npm run typecheck` 加到 `preview:pack` 的第一步；独立 `preview:verify` 仍只检查现有产物结构。
- 新增隔离负向测试：删除页面组件属性后，打包命令须在构建前非零退出且不产生 `dist/preview/index.html`。

## 最终修复、验证与预防

`npm run preview:pack` 现在依次执行类型检查、构建和结构审计；正常包、独立验包及预览回归测试均通过。隔离缺失组件用例在类型检查阶段失败，并确认没有新生成入口文件。公开扫描、Markdown 链接与差异检查通过。

今后将打包命令作为交付门禁时，应确认类型检查在任何产物写入之前运行，并保留缺字段导致提前失败的隔离测试。类型检查和静态验包均不能替代目标浏览器交互验收。若原始复现再次出现，沿用本编号重开。

证据：[Issue #77](https://github.com/TgStudio-PM/PM-product-workflow/issues/77)、`tests/preview-pack.test.mjs` 及关联 PR 的 CI。
