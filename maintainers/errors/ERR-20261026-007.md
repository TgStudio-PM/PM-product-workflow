# ERR-20261026-007：材料申报本地记录误锁定与超长恢复截断

- 状态：已解决（Issue #127/#168；本轮超长恢复边界已修复并完成定向浏览器与独立完整性核验）
- 日期：2026-10-26
- 范围：Issue #127/#168；原生案例与可选 Vue starter 的浏览器本地记录恢复

## 现象与复现

使用原创虚构的 DOM 与浏览器存储桩运行仓库当前 `app.js`：记录为 `{description:"",materials:[],status:"已提交"}` 时，页面恢复为 `submitted`，申请说明 `disabled=true`，两项必备材料均未选。该结果与外部报告的 DOM 模拟线索一致；本仓库复现实际运行了当前脚本，但不是目标浏览器验收。

错误特征：本地记录只有“已提交”标记、缺必填说明或必备材料，页面仍显示提交成功并锁定表单。

## 影响与根因状态

根因已定位：`readState()` 只按存储中的状态字符串还原“已提交”，`restoreDraft()` 随后直接锁定；恢复时没有重新检查 BR-002、BR-003 与 BR-005 的前提。仅涉及完全虚构的静态教学案例和浏览器本地状态，不涉及真实办件、服务端权限或生产数据。

## 尝试及结果

1. 对照案例事实规则和可选 Vue 案例的异常恢复边界，固定最小虚构反例。
2. 原生页面恢复时重新检查说明与必备材料；无效记录保留可用字段、降为草稿，尝试更正存储并如实提示写入结果。
3. 定向测试覆盖说明为空、缺任一必备材料、有效已提交记录、更正写入失败和再次加载；正常提交条件、存储键及材料范围未变。

## 2026-10-30 Issue #168：超长记录恢复边界复发

- 基线：`main` `6a4a51c86f4d1370a375ff39759a83cf7a08b959`；范围扩展至原生案例与可选 Vue 模板的同类本地状态恢复，不涉及真实资料。
- 原创输入：`A` 重复 500 次再加“尾”，共 501 个既有页面计数单位。Chrome `155.0.8059.86`、`file://`、1440×900、DSF 1，原生/Vue 各草稿与已提交共四种组合全部实际复现；该旧源复现不是修复验收。
- 现象：四例界面均被截为 500 且丢尾；两种草稿显式暂存后，存储也由 501 覆盖为 500；两种已提交记录仍只读锁定，原存储保持超限的 501 字。
- 根因：两个读取器先 `slice` 截断正文，使恢复后的值看似符合上限；提交及终态恢复又未独立核对长度条件。旧空说明/缺材料回归未覆盖这一边界，不能据其通过推断所有无效终态都安全。
- 影响：需求上限变化或旧记录超限时可能丢失既有内容，也可能将不满足 BR-002 的记录误锁定。修复方向为保留完整原文、超限降为可编辑草稿、提示修正并在提交时再次校验；既有 500 字和材料规则不变。
- 修复：原生与 Vue 读取均保留完整超限文本；超限草稿可编辑和暂存，但不能提交；超限旧“已提交”记录转为草稿并提示更正保存结果。500 字上限、材料规则、存储结构、键和接口均未改变。
