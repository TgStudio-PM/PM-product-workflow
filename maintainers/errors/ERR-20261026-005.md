# ERR-20261026-005：静态交付漏验 object data 与 video poster

- 状态：已解决（静态结构审计范围；目标浏览器未作本轮复验）
- 日期：2026-10-26
- 范围：Issue #123；`pm-prototype-packager` 静态预览打包与独立 ZIP 验包

## 现象与复现

在当前公开基线，以完全虚构的 `index.html` 包含 `<object data=missing.pdf></object><video poster=missing.png></video>`，直接调用 `_audit_static`，返回 `ACCEPTED_MISSING_RESOURCES`，没有报缺失资源。复现只解析文本，不运行 HTML 或访问网络。

错误特征：HTML 显式声明嵌入文档或视频封面资源，但交付包未含目标文件，结构审计仍报告成功。

## 影响与根因状态

根因已定位：`_ReferenceParser` 将 `src`、`srcset`、部分 `href` 等加入资源引用列表，但 `object.data` 只检查可执行 `data:` URI，`video.poster` 没有加入列表。`_audit_static` 仅对已收集的引用执行 `_resolve_reference`，因此遗漏两种属性。受影响的是静态结构审计结论；没有证据表明真实项目交付包曾因此缺文件，也不能由静态检查推断目标浏览器运行结果。

## 尝试及结果

1. 已用最小虚构 HTML 固定原始反例，并核对相邻的 [ERR-20261024-004](ERR-20261024-004.md)：它解决可执行 `data:` URI 边界，没有解决普通 `object.data` 本地路径或 `video.poster`。
2. 将两个属性的非空值送入现有引用解析；`object.data` 的可执行 `data:` URI 拒绝逻辑保留。
3. 虚构定向用例分别验证缺失、远程/绝对引用、白名单本地资源与图片 `data:` 兼容；重新签名的 ZIP 独立验包也拒绝两种缺失引用。

## 修复、验证与预防

原始反例在修复后分别返回 `ASSET-03`；`python -m unittest discover -s .agents/skills/pm-prototype-packager/tests -p 'test_*.py' -v`：共 45 项，44 项通过、1 项因 Windows 无法创建符号链接而跳过（与本次属性用例无关）。仓库治理测试 16 项通过；三类虚构 Profile 均完成实际构建和独立 ZIP 验包；公开内容扫描、Markdown 链接检查和 `git diff --check` 通过。GitHub Linux CI 结论另见关联 PR，不能由本地结果预先代替。

预防要求：新增静态资源属性检查时，同时覆盖缺失、远程/绝对引用、有效白名单文件及独立 ZIP 验包；保留非执行图片 `data:` 的现有兼容行为。检查结果只表示已识别引用的包内结构，不代表浏览器离线或产品验收。

证据：[Issue #123](https://github.com/TgStudio-PM/PM-product-workflow/issues/123)、当前公开 `package.py` 的解析器与 `_audit_static`、虚构最小复现。
