# ERR-20261023-001：离线预览清单失真仍被验包接受

- 状态：已解决
- 日期：2026-10-23
- 范围：Tg Studio Vue 原型工程模板的离线预览构建与验包；Issue #65

## 现象与复现

在忽略目录的独立副本中，将旧版离线包 `manifest.json` 的页面标题改成错误值，并把 `files` 改成不存在的 `missing-runtime.js`，运行旧版 `node scripts/verify-preview.mjs` 仍输出“离线包审计通过”。本机保留旧版副本与复现结果，未修改真实项目资料或已发布文件。

错误特征：manifest 元数据与页面注册表、`PAGES.md` 和实际产物不一致，但验包退出码为 0。

## 影响与根因

使用 manifest 读取页面标题或文件范围的接收方可能得到错误信息，验包却给出通过结论。根因是旧版构建未将 `manifest.json` 纳入 `SHA256SUMS`，旧版验包仅检查路由存在及页面数量，未核对标题、文件列表和清单摘要的完整集合。当前只证明静态元数据误验，不推断浏览器页面已出错。

## 尝试及结果

- 旧版验包对伪造标题及文件列表均误报通过，复现稳定。
- 调整构建顺序，先写 manifest，再计算五个内容文件与 manifest 的 SHA-256。
- 验包核对 manifest 名称、页面路由与标题、`PAGES.md`、文件列表以及摘要条目的缺失、重复和额外情况。

## 最终修复、验证与预防

新版正常预览包通过 `npm run preview:pack` 与 `npm run preview:verify`。新增的 6 个隔离 Node 测试覆盖正常包及伪造标题、伪造文件清单、未同步摘要的 manifest 篡改、缺失摘要、重复和额外摘要；本机全部通过。`npm run typecheck`、公开内容扫描、Markdown 链接和差异检查通过。GitHub CI 结果以关联 PR 为准。

以后改变离线包元数据时，必须同时定义 manifest 与实际内容的对应关系，并保留独立副本的负向验包测试。旧版生成的包须重新执行 `preview:pack`，新版验包会拒绝缺少 manifest 摘要的旧清单。本修复提高偶发失真检测能力，不构成防恶意重签名或浏览器 `file://` 运行验收。
