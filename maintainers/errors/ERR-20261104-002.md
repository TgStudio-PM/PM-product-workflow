# ERR-20261104-002：预览验证测试缺少构建夹具前置说明

- 状态：已解决（Issue #181 最小前置提示已集成，候选源码哈希与正式分支一致）
- 时间：2026-11-04 10:04:11 +08:00
- 范围：[Issue #181](https://github.com/TgStudio-PM/PM-product-workflow/issues/181)；`starters/vue-prototype` 预览校验测试入口与使用说明

## 现象与复现

在全新副本执行 `npm ci` 后，`dist/preview` 尚不存在；直接运行 `npm run test:preview-verify` 返回非零，TAP 汇总为 63 tests、15 pass、48 fail。失败由多个夹具复制尝试共同依赖缺失的 `dist/preview` 引起，属于未说明前置后的级联，不代表 48 个独立业务错误。先运行 `npm run preview:pack` 后，原测试命令 73/73 通过。

## 影响与根因

干净安装后直接运行测试会把准备夹具失败表现为大量 `ENOENT`，使测试结果难以解释。根因是 `tests/verify-preview.test.mjs` 的 `createFixture` 从 `dist/preview` 复制预览包，但 `test:preview-verify` 不生成该包；README 单独说明了 `preview:pack`，没有写出测试命令必须先依赖该构建产物。

## 尝试结果

- 全新跟踪文件副本复现缺件失败；`npm run preview:pack` 成功后，原测试命令通过。
- 首次新增 CLI 回归用例时，子进程继承 Node test runner 的 `NODE_TEST_CONTEXT`，递归的 `node --test` 被 runner 跳过，导致子进程状态断言失败。只在子进程环境副本中删除该变量后，隔离 CLI 回归通过；Node v20.20.0 的对应行为见 [test runner source](https://github.com/nodejs/node/blob/v20.20.0/lib/internal/test_runner/runner.js#L543-L546)。
- 初次隔离准备曾因临时副本路径映射错误，使 `npm ci` 在缺少 package lock 的 cwd 报 EUSAGE；这是测试准备错误，没有进入产品复现，原始记录保留在本机。

## 修复与验证

`verify-preview.test.mjs` 在任何夹具创建和测试注册前访问 `dist/preview`：仅遇到 `ENOENT` 时抛出明确提示“Run npm run preview:pack before npm run test:preview-verify”；权限及其它错误原样抛出。目录存在时继续执行原有测试。`preview-pack.test.mjs` 新增隔离 CLI 回归，确认缺件时返回非零并显示前置提示。README 写明依次执行 `npm run preview:pack`、`npm run test:preview-verify`，并说明测试命令不会自动重建预览包。

在 Node v20.20.0、npm 10.8.2 下，干净副本 `npm ci` 退出码 0；无预览包时测试命令退出码 1、17 tests 中 16 pass、1 fail，唯一失败明确报告缺件；`preview:pack` 退出码 0；构建后测试命令 74/74 通过。候选三文件 SHA 与正式分支一致；本机验收 receipt SHA256：`53c5a790215f0d362332fd54a9ebfc4e3c5dd4338512301a4f54abdb95b3bca7`。这些工程检查不代表浏览器、目标产品经理或 Release 验收；PR CI 结果由对应 PR 记录。

## 预防

测试夹具依赖构建产物时，应在入口明确说明前置条件，并以显式非零诊断阻止级联错误。本测试入口保留单独的构建步骤；测试汇总失败数不能当作同等数量的独立业务缺陷。
