# ERR-20261104-009：既有工作区改动被误归为本轮差异

- 状态：已解决（限本次原创只读接续的增量归因复验）
- 日期：2026-11-04
- 范围：[Issue #199](https://github.com/TgStudio-PM/PM-product-workflow/issues/199)；原型交接只读接续中的工作区增量归因

## 现象与复现

原创只读接续材料已说明源文件在开始时存在未提交修改，且本轮仅改文档、未改源码；接续者也识别了已完成实现和未确认的接口契约，但仍把该源文件的 dirty 状态列为本轮范围差异。主线起始快照与源码哈希证明本轮未改该源码，当前 diff 对应既有用户备注。

复核交接中的开始状态、任务范围和起始快照，再与当前工作树及差异对照，可复现“将 dirty 状态直接归入本轮”的错误表达。这不证明发生越权写入或重复执行代码；输出证据也不能说明更深层原因。

## 错误特征与影响

- 错误特征：输出将 dirty 状态列为本轮范围差异，未体现它与交接所述起始既有改动的区分。
- 影响：可能误报范围冲突，并阻塞独立且已授权的工作。
- 根因状态：未定位；已确认输出没有区分既有改动与本轮增量，底层原因待查。

## 尝试与候选修复

既有 [ERR-20261029-001](ERR-20261029-001.md) 记录的过期当前状态问题已单独关闭；本条只处理工作区改动的来源归因，不扩展其关闭范围。

已在原型交接 Skill 的准备和接续步骤中加入最小规则：记录开始时已有改动与本轮增量；接续时将当前 diff 与起始现场或可用基线证据比较。单独的 dirty 路径不作为范围冲突证据；来源未核实时如实标记，不报为已确认冲突，也不阻塞独立已授权工作。不要求默认建立全项目快照。

## 待验证与预防

待主线以独立只读复验确认：接续者能识别开始时已有的 dirty 改动，不把它归为本轮差异，同时准确标记来源证据不足的情况。复验完成前保持缓解中，不标记已解决。

后续交接应记录实际起始状态和本轮增量；接续判断须对照现有起始记录或可用基线证据，不能仅凭当前工作树状态归因。

## 独立复验与关闭范围

使用同一项目、同一交接与更新后的方法进行无旧聊天的独立只读复验。接续者检查 HEAD 与当前 diff，区分当前源码、备注改动和交接记载的起始现场；未再仅凭 dirty 路径报本轮范围冲突，无法独立核实的改动时点仍保留待确认，也没有重复代码任务或推断接口可实现。

新报告初稿另有一处起始文件清单归属表述错误；原件保留后，按实际交接中的清单校正为新版，不称首次全无误。主线实读新版与差异，并核对八份输入文件字节、HEAD、索引条目、工作树状态及旧报告均未改变。

本次关闭只说明上述归因用例未再出现原错误，不证明所有改动来源已查清，也不等于浏览器、运行时、产品经理或生产验收。底层模型遗漏机制仍未定位；本次修复是可定位的工作流指引补足。格式、链接与公开内容检查及最终 CI 以对应 PR 记录为准。
