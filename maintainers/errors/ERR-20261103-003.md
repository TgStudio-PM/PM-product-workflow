# ERR-20261103-003：同名重建覆盖既有交付 ZIP

- 状态：已解决（Windows 本机定向回归与 Linux CI 已核对）
- 日期：2026-11-03
- 范围：Issue #176；原型交付 ZIP 构建与独立验包流程

## 现象与复现

同一输出路径先成功生成 V1，再修改源内容并运行第二次构建；旧版脚本静默将 V1 替换为 V2。旧 CLI probe receipt SHA-256 为 `fd27d4fa11f6c3450353ebe60e7465f1b903f0d4141a9935e9d858ce5afb9276`；探针记录的 V1 SHA-256 为 `b45c29a82103631a7f732f1aa389d8d03d88f56b6c6477c1b3cf0f45358dd61e`，同名 V2 SHA-256 为 `f62f2da5a91015e0790f1797fbaa6c6374750c6fbaee2f18e65a91d34a83389b`。保护旧包未造成 V1 字节损失。

## 影响与根因

同名重建会使原候选失去原路径上的字节身份；之后继续验包或解压还可能误把旧包状态和新一轮工作混淆。根因是构建在临时归档校验后调用 `os.replace`，其语义允许覆盖既有目标。

## 修复与验证

构建现在预先拒绝已存在的文件、目录或末级符号链接，并在发布阶段使用平台原生的排他操作；同名竞争由 `OUTPUT-02` 拒绝，提示选择新名称。输出父目录先规范化，末级名称保留，避免跟随既有或悬空链接。

`python -m unittest discover -s .agents/skills/pm-prototype-packager/tests -v`：共 57 项，54 项通过、3 项因当前 Windows 环境的符号链接权限跳过。Windows 本机通过 `os.rename` 发布分支。

## 预防规则与边界

每轮使用新的 ZIP 文件名和对应的空解压目录。遇到 `OUTPUT-02` 后选择新名称并停止后续验包/解压命令；检查既有包时直接运行 `--verify`。示例命令须在构建和验包失败时立即停止，解压不得使用 `-Force`。本次未重跑浏览器、产品经理、真机或生产验收；打包与归档变化不构成这些验收。
