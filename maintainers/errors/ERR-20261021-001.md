# ERR-20261021-001：格式化命令截断新文档

- 状态：已解决
- 日期：2026-10-21
- 范围：Issue #28 的新产品使用指南

## 现象与复现

对 `docs/product/USING_SKILLS.md` 调用 Python `Path.write_text(..., newline=...)` 时，传入的换行参数因命令转义变成字面量 `\n`，触发 `ValueError: illegal newline value`。写入模式已打开目标文件，文件被截断；后续命令未检查失败退出码，仍执行 `git add`，将空文件暂存。

错误特征：写入命令报错后，目标文件长度变为 0，暂存区对应 blob 也为空。

## 影响与根因

若直接提交，将丢失新指南内容并产生错误的验收结论。本次在提交前由差异和文件长度检查拦截，尚未推送。根因是错误的换行参数转义，以及把修改、暂存、校验串在一起却没有在失败时停止。

## 尝试及结果

- 原格式化命令失败，截断目标文件。
- 第一次恢复尝试从已暂存内容读取，但暂存区已被空文件覆盖，只写回一个换行；失败后停止继续猜测。
- 使用 `git fsck` 定位之前暂存留下的完整 blob，核对首行和末尾后按字节恢复；成功。

## 最终修复、验证与预防

从完整 Git blob 恢复指南，并将末尾整理为单个换行。恢复后检查文件长度与内容，Markdown 链接、公开内容扫描和 `git diff --cached --check` 均通过。

以后对文档做格式化时先保留可恢复副本或暂存 blob；每个可能失败的写入步骤都单独检查退出码和文件长度，确认内容无误后再暂存，避免把错误结果覆盖到索引。
