## 现象与影响

执行 `page:new` 时未显式锁定并核验目标 cwd，命令在正式 `starters/vue-prototype` 下运行，意外生成 `issue172-check` 第三页候选文件。此前关联的 `preview:pack` 实际使用更早复制的两页临时副本，因此不能作为新增第三页后的验证证据。该问题属于本次调用工作目录错位，不是 `page:new` 越界漏洞。

曾尝试递归清理，但工具拒绝该操作；删除未成功，之后停止清理。主线核对正式 registry diff 为空、三个新增文件均为未跟踪项后，按路径和文件清单核验并将其 `Move-Item` 到专用私有 Temp 保全。恢复回执记录三文件移动前后 SHA-256 一致及 `sourceRemovedByMove: true`；不将被拒绝的递归删除描述为成功。

## 根因与处理

已确认根因是执行脚手架前未将 cwd 固定到目标绝对路径并做边界断言。隔离试验改为每个写命令先解析 cwd，断言其位于本任务唯一 Temp 根目录且不在正式仓库，再通过绝对 `workdir` 执行。

- 正式源只通过 profile 白名单打包一次；打包与独立验包 exit 0。ZIP 含 59 个源文件，其 SHA-256 与当前正式 starter 逐项一致；禁入目录为 0。
- clean-source 中 `npm ci`、`npm run preview:pack` 均 exit 0；中文/空格正向与碰撞测试 8 通过、32 跳过、0 失败。
- 将 clean-source 与依赖独立复制至另一 Temp 后，`page:new -- tg-studio-check route-check "Tg Studio 第三页验证"` exit 0；基线两页和原标题、顺序保留，新增第三页已进入 registry。该副本 `preview:pack` exit 0，正向集成测试 1 通过、33 跳过、0 失败。
- 正式 registry Git blob 前后均为 `c912613e6d2f512596e1a8f054551223a67448d2`，diff 为空；正式树无本次意外新增的源文件。

## 预防与证据

任何脚手架或构建写命令执行前，先用绝对路径锁定 `workdir`，在命令内检查解析后的 cwd 位于专用 Temp 且不属于正式仓库；不得依赖上一个命令的 `cd` 或当前会话状态。该规则关闭本次错位，不保证未来不会发生同类错误。
