# ERR-20261026-001：引用式 Markdown 相对链接未纳入交付验包

- 状态：已解决（常见完整与折叠引用式语法）
- 日期：2026-10-26
- 范围：ZIP 打包和独立验包中的 Markdown 相对链接检查；Issue #111

## 现象与复现

旧实现对正文 `[setup][steps]` 和定义 `[steps]: missing.md` 未报错，尽管目标文件不存在。Issue #111 的最小复现调用 `_audit_markdown({'docs/guide.md': b'[setup][steps]\n\n[steps]: missing.md\n'})` 返回成功。

错误特征：ZIP 清单及文件摘要有效，但接收者点击已定义的引用式链接时，目标未随包交付。

## 影响与根因

接收者可能无法打开交付文档实际使用的包内链接，打包和独立验包会漏报断链。根因已定位：审计器只扫描 Markdown 行内链接，没有解析被使用的引用标签与其定义。

## 尝试及结果

- 将审计范围限定为正文实际使用的完整 `[text][label]` 与折叠 `[label][]` 引用；不扫描 shortcut-style `[label]`，也不引入完整 CommonMark 解析器或外部依赖。
- 实现标签大小写不敏感、空白折叠；引用定义支持尖括号包围的含空格目标及同一行常见可选标题。未使用定义、代码、外链和纯片段跳过。

## 修复、验证与预防

打包与独立验包现在对使用中的完整/折叠引用式目标复用 `MARKDOWN-01/02` 相对目标检查；新增目标存在/缺失/逃逸、标签规范化、尖括号空格路径与标题、未使用定义、代码、外链/片段和重新计算清单及摘要后的独立验包拒绝测试。原行内链接检查保持适用。

- `python -m unittest discover -s .agents/skills/pm-prototype-packager/tests -p 'test*.py'`：41 项通过，1 项因当前 Windows 环境无法创建符号链接而跳过。
- `python -m unittest discover -s maintainers/tests -v`：14 项通过，含三类 Profile 打包与独立验包回归。
- `python maintainers/scripts/check_public_content.py --root .`：公开内容扫描通过；此调用未提供基线参数，变更风险分类显示 `NOT-EVALUATED`。
- `python maintainers/scripts/check_markdown_links.py .`：通过。
- 三类官方 Profile 在本机忽略目录各生成一次并独立验包：静态预览 `536269CFA226276180D92E5C049744BDB137DF71CDA0CE3CA0D9AC6FC602946C`、前端源码 `B87A3AF8A75F13F8ED28FFDBAA58E0EA3AD915A9D45371517E95F932359DF42E`、后端需求 `E33A885D6ECE76F5563BE9E5C255FBCE2CED3C46FAD39CB3DA9F459930D2A4F3`（SHA-256）。这些是临时验证候选，不发布或提交。
