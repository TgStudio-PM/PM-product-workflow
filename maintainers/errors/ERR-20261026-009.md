# ERR-20261026-009：Vue 离线预览误拒绝内嵌栅格 CSS 图片

- 状态：缓解中（静态修复已在工作分支验证；目标浏览器 `file://` 渲染和 PR 合并仍待完成）
- 日期：2026-10-26
- 范围：Issue #75；可选 Vue starter 的 CSS 离线预览审计

## 现象与复现

在完全虚构的隔离 Vue 工程中，向 `src/style.css` 引用本地小型 PNG。Vite 构建成功，将它内嵌为 `url(data:image/png;base64,...)`；旧版 `preview:verify` 报“样式表包含外部或绝对 URL”，退出码 1。反例来自[Issue #75](https://github.com/TgStudio-PM/PM-product-workflow/issues/75)，不涉及真实项目或第三方图片。

错误特征：本地栅格图片已进入同一份 CSS、无需外部资源，验包仍按任意 scheme URL 拒绝。

## 影响与根因状态

根因已定位：CSS `url()` 的 scheme 门禁没有区分 Vite 内嵌的图片数据与外部引用。旧规则保障远程资源禁入，但也误拒绝了可离线审计的本地小图片。影响可选 Vue starter 的静态包生成，不代表既有页面曾发生浏览器白屏或生产故障。

## 尝试及结果

1. 保留远程、绝对、越界路径和 CSS `@import` 的既有拒绝规则。
2. 仅对 `data:image/png`、`jpeg`、`gif`、`webp`、`avif` 的规范非空 Base64 URI 放行；其余 `data:` 用统一错误提示拒绝，不在日志回显载荷。检查 MIME 和编码语法，不声称解码后一定是有效图片。
3. 测试运行时用 Node 内建模块原创生成 1×1 PNG，在隔离工程实际执行 Vite 构建与独立验包；对五种允许的 MIME 及 SVG、非图片、畸形编码逐项验证。合法图片 URI 放在 `@import` 中仍须拒绝。

## 修复、验证与预防

原始 PNG 内嵌反例在新规则下通过独立静态验包；负例各自重算 CSS 摘要后仍被拒绝。`npm run test:preview-verify`、`npm run typecheck`、`npm run preview:pack` 的本地结果及 GitHub CI 见关联 PR；目标浏览器 `file://` 图片渲染和网络请求尚未复验，不把静态审计当成浏览器验收。

预防要求：调整离线审计时同时保留可核对的本地资源正例与外部/可执行/畸形资源负例；每个负例独立验包。允许的 URI 类型应保持窄范围，不能扩展为任意 `data:` 通行。

证据：[Issue #75](https://github.com/TgStudio-PM/PM-product-workflow/issues/75)、`starters/vue-prototype/scripts/verify-preview.mjs`、`starters/vue-prototype/tests/verify-preview.test.mjs`。
