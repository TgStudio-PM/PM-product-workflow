# ERR-20261024-005：页面脚手架在无尾随逗号的注册表中误报成功

- 状态：已解决
- 日期：2026-10-24
- 范围：Tg Studio Vue 原型工程新增页面命令的候选实现；Issue #85

## 现象与复现

在隔离的虚构 starter 副本中，将 `pageRegistry` 最后一项写成合法的无尾随逗号形式，然后运行候选 `page:new` 命令。初版命令报告已创建页面并写入注册表，但 TypeScript 解析新文件时报告 `',' expected.`。复现只使用虚构页面和隔离副本，未修改真实项目或仓库已有页面。

错误特征：命令退出成功，生成的页面注册表却有语法错误；共享页面读取器在 TypeScript 错误恢复后仍可读出路由，因此仅检查页面清单会漏掉此问题。

## 影响与根因

使用者可能得到看似成功、实际无法类型检查和运行的新增页面。初版插入逻辑假定原注册表最后一项已带逗号；生成后只复用页面元数据读取器，没有核对 TypeScript `parseDiagnostics`。这是公开 PR 合并前发现的候选实现错误，不表示已合并基线发生故障。

## 尝试及结果

- 固定无尾随逗号的合法注册表作为隔离复现，确认初版命令误报成功且生成文件有语法诊断。
- 在最后一项确实缺少尾随逗号时补充分隔符，并在任何写入前检查生成注册表的 TypeScript 解析诊断；仍复用页面读取器核对路由和标题。

## 最终修复、验证与预防

新增无尾随逗号回归测试，确认生成文件没有语法诊断且原页面和新页面均可读。`npm run test:page-new` 的 7 项测试、原 starter 类型检查与离线打包/验包通过；独立克隆及前端源码 ZIP 解压副本的实际新增页面、类型检查与离线清单核对也通过。CI 结果以关联 PR 最终提交为准；浏览器交互与非开发产品经理计时人测未执行。

预防规则：改写代码结构时，静态元数据读取成功不等于源文件语法有效。生成工具必须覆盖合法的可选分隔符格式，并在写入前核对语法，再用类型检查与实际构建验证生成结果。

证据：[Issue #85](https://github.com/TgStudio-PM/PM-product-workflow/issues/85)、[PR #86](https://github.com/TgStudio-PM/PM-product-workflow/pull/86) 和 `starters/vue-prototype/tests/create-page.test.mjs`。

## 2026-10-24 后续复开：独立验包仍接受语法无效注册表

Issue #89 隔离复现了同一错误恢复盲点在另一个调用路径中的表现：给 `src/app/page-registry.ts` 末尾追加 `const =` 后，TypeScript AST 存在解析诊断，但共享读取器仍返回原有页面，独立 `node scripts/verify-preview.mjs` 对原有完整包仍退出 0。该问题会让使用者把语法无效的源码与已有离线包误判为一致。复现仅使用虚构 starter 隔离副本，包内文件及其 SHA-256 保持不变。

因此沿用 ERR-20261024-005 重开，而不是另立同根因记录。修复是在共享读取器提取静态路由前检查 TypeScript `parseDiagnostics`，有语法错误即以不包含源码内容的说明拒绝；不执行完整类型检查。这样独立验包、直接预览构建和页面脚手架均使用同一语法门槛。

回归验证包括：有效字段重排和可选尾随逗号仍通过；非法注册表令独立验包与直接构建失败，原有 `SHA256SUMS` 不变；`page:new` 不创建页面目录也不改注册表。当前本地预览测试 13/13、页面脚手架测试 8/8、类型检查、`preview:pack`、`preview:verify` 和差异检查通过；GitHub CI 待关联 PR 完成。本次扩展现已修复，错误状态为“已解决”；目标浏览器交互与非开发产品经理人测不属于此项验证。可复现证据：[Issue #89](https://github.com/TgStudio-PM/PM-product-workflow/issues/89)、`starters/vue-prototype/tests/verify-preview.test.mjs` 与 `create-page.test.mjs`。
