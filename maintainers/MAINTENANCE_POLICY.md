# 分级维护规则

本规则用于减少个人维护者的重复审批成本，同时保留 PR、验证记录和重要决策的人工作用。风险无法确定时提高一级；所有非微小变更必须通过 PR，不得直接推送 `main`。

## 低风险

包括错别字、普通链接、格式、模板小幅补充、既有测试修正、虚构数据调整和不改变行为的整理。

Coding Agent 可以在完成差异检查、相关验证和开源边界检查后合并，并在阶段汇总中报告。

## 中风险

包括新增 Skill、新增虚构案例阶段、目录调整、Profile 规则扩充和不破坏现有用法的功能变化。

Coding Agent 应创建 PR，说明行为变化、开源边界检查和完整验证；检查通过后可以合并，并在里程碑结束时汇总。

## 高风险

包括以下内容：

- 修改项目定位、核心原则或目标使用者。
- 修改开源边界、License、版权或第三方授权结论。
- 从真实项目、真实对话或内部材料提炼公开内容。
- 删除或重命名公开能力，或引入重大不兼容变化。
- 修改 CI、敏感扫描、风险识别、分支或合并规则。
- 创建正式版本、发布包或对外发布声明。
- 自动检查发现敏感信息、来源不清或授权证据不足。

高风险变更必须完成可审阅的 PR，由产品负责人明确确认后才能合并。路径和内容任一命中高风险即可升级，不能只依赖 Coding Agent 的主观判断。

## 所有合并的最低要求

1. PR 说明具体问题、最终行为和验证结果。
2. 受影响的文档、模板、案例和规则保持一致。
3. 产品验收与机器验证分别记录；不适用时说明原因。
4. 执行开源边界检查，不包含真实项目材料、本机路径、凭据或未授权资产。
5. 验证失败、事实冲突或来源不足时不得合并。
6. 自动合并仍需等待必要检查完成，不能绕过 PR 或检查结果。

产品负责人可以随时针对某次变更提高风险级别、暂停自动合并或撤销本规则。
