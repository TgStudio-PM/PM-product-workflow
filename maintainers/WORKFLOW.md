# 接力维护流程

本流程让任意新会话或 Coding Agent 可以仅依赖仓库继续维护 PM-product-workflow。

## 任务开始

1. 读取根目录 `AGENTS.md` 及其指定的必读文件。
2. 读取关联 Issue、PR、ADR 和任务涉及的 Skill、Profile 或模板。
3. 获取远端状态，核对本地提交、远端 `main`、关联 PR、已有分支和最近接力块；不得只依据旧克隆或长期记忆。
4. 判断风险等级；无法确定时提高一级。
5. 从远端最新 `main` 使用 `feature/*`、`fix/*`、`docs/*`、`chore/*` 或 `refactor/*` 分支；不复用已合并分支。

一个任务只保留一个核心目标。需要改变目标时先更新 Issue 或拆分任务。

## 开发过程

- 当前明确决策改变旧规则时，同步权威文档并记录 ADR。
- 真实材料只在公开仓库之外提炼；公开内容重新创作。
- 两次等价失败后停止盲试，并按错误治理规则记录。
- 只读取完成任务所需的上下文，不依赖未落盘的历史聊天。

## 完成与合并

PR 必须说明问题、最终行为、风险等级、影响范围、产品验收、机器验证、边界检查、未决项和兼容性影响。

所有变更都通过 PR 留痕。低、中风险在自审和检查通过后可以合并；高风险停在合并前等待产品负责人确认。不得直接推送 `main`。

## 中断与换会话

未完成任务在 Issue 或 PR 中留下 `maintainers/templates/maintenance-handoff.md` 定义的接力块。已完成并合并的任务由 Git 历史、PR 和 ADR 保存，不建立长期堆积的交接归档。

新会话使用以下启动指令：

> 读取根目录 AGENTS.md，按规定加载当前项目状态；核对关联 Issue、PR、分支差异和最近接力块，再从“下一步”继续。不得把历史聊天当作未落盘事实。

## 空白会话测试

每个里程碑至少执行一次：

1. 新会话只获得仓库地址。
2. 读取 `AGENTS.md` 后复述定位、边界、当前状态和下一步。
3. 接手一个未完成 Issue 或 PR，不查询旧对话。
4. 完成修改、验证和接力记录。
5. 若仍需旧聊天，补齐缺失的仓库事实后重新测试。
