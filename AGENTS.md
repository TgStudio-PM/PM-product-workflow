# Repository Instructions

## Purpose

This repository maintains a Coding Agent workflow for product managers working on government and complex enterprise products.

## Working rules

1. Read the relevant project and module facts before changing a prototype or workflow.
2. Separate confirmed facts from pending questions. Do not invent APIs, production behavior, policies, organizations, or personal data.
3. When implementation changes a confirmed rule, update the affected fact files in the same change.
4. Classify UI review findings as business errors, profile violations, or subjective design suggestions.
5. Report product-manager acceptance and machine verification separately.
6. Check `docs/open-source-boundary.md` before every contribution.

## Merge authority

Follow `docs/maintenance-policy.md`. Low-risk and medium-risk changes may be merged after the documented validation without waiting for manual approval. High-risk changes require the product owner's explicit approval before merge.

## Completion report

State the result, changed files, validation performed, pending questions, and material risks.
