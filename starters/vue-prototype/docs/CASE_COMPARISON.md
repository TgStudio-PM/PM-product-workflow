# 材料申报案例：原生版与 Vue 模板版

本页对照仓库内两个独立的、完全虚构的教学实现，帮助读者理解工程结构变化。Vue 版沿用材料申报案例的 BR-001 至 BR-007 规则，但增加了概览页面与工程模板示例。两者不是生产系统，也不代表视觉完全一致。

| 对照项 | 原生案例 `examples/material-submission/` | Vue 模板案例 `starters/vue-prototype/` |
| --- | --- | --- |
| 页面与规则 | 单页材料申报；业务规则记录在案例 facts 文档中 | 概览页与材料申报页；材料申报规则仍按 BR-001 至 BR-007 管理，页面旁有 `RULES.md` 并链接模块 facts |
| 结构与复用 | 单个 HTML、CSS、JavaScript 文件直接组成演示页 | Vue 单文件组件、页面注册表、可复制页面模板及查询、表格、表单、确认弹窗、详情等共享组件 |
| 案例状态 | 材料申报页包含草稿与已提交状态 | 材料申报页显示草稿或已提交状态；概览页展示页面注册表元数据 |
| 草稿存储 | 浏览器本地存储；自动暂存并在刷新后恢复 | 浏览器存储适配层；自动暂存并在刷新后恢复，页面与存储适配器分开 |
| 提交 | 校验申请说明和两项必备材料；提交后控件只读，不发起服务端请求 | 使用相同的必备材料规则；提交后控件只读，不发起服务端请求 |
| 重置 | 浏览器原生确认后，只清除本案例存储键并回到空白草稿 | 共享确认弹窗确认后，只清除本案例存储键并回到空白草稿 |
| 编辑与预览 | 可直接打开 `index.html` 查看单页演示 | 用 Vite 开发服务器热更新；通过 `npm run preview:pack` 构建独立静态预览目录，并用 `npm run preview:verify` 检查包结构 |
| 前后端协作 | 通过案例事实与规则理解虚构交互 | 增加数据适配层与 `contracts/`；列出已确认的虚构数据结构和待确认的接口问题，不定义真实 API |

## 阅读建议

- 先打开[原生离线案例](../../../examples/material-submission/index.html)，了解业务交互与规则。
- 再打开 Vue 模板的[概览页](../src/modules/overview/pages/home/Page.vue)和[材料申报页](../src/modules/material-submission/pages/apply/Page.vue)，查看相同案例规则如何落到模块、组件、存储适配和前后端协作材料中。
- Vue 模板的实现边界与使用方式见[模板说明](../README.md)。

两种实现都只在当前浏览器保存虚构演示状态，不上传材料、不执行真实办理。对照用于解释代码组织与交付方式的差异，不构成对任一视觉效果的等同承诺。
