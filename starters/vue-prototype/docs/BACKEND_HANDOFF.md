# 后端接口交接说明

此工程没有生产后端，也没有已确认的 API 地址或 HTTP 方法。新模块需要与后端协作时，按需复制仓库的[可选模块 API 对接记录模板](../../../templates/optional/API_HANDOFF.md)到使用者模块的 `contracts/API_HANDOFF.md`。它不随 `templates/module/` 整目录复制自动带入；在该文件集中维护原型当前字段、待确认的服务端字段和接口、确认依据及验证结果。服务端字段和接口实现细节由前后端共同确认，业务含义与规则须依据模块事实并由产品负责人确认，只有相应责任人确认后才能标记为已确认。

`src/modules/material-submission/contracts/README.md` 是完全虚构的材料申报案例的既有讨论材料，描述该案例的示例数据结构和待确认项。它仅适用于该教学案例，不是生产契约，也不是其他模块的事实来源。新模块应记录自己的证据，并避免复制案例字段或把 mock 行为当作服务端行为。

## 对接评审时请确认

- 接口 URL、HTTP 方法、API 版本、环境和网关约束。
- 认证方式、身份上下文、角色权限和数据范围。
- 查询、暂存、提交、撤回/清除等操作的服务端语义。
- 请求与响应字段、必填/可空、枚举、时间、ID 和版本字段。
- 文件是否由服务端接收；上传接口、格式/大小限制和扫描规则。
- 分页、排序、并发更新、幂等和重复提交行为。
- 业务错误码与字段校验错误结构，哪些错误可重试。
- 持久化、审计和保留策略，以及联调和验收环境。

只有双方确认后才将结论标记为已确认。当前材料申报原型中的“暂存”“提交”和“清除”均在浏览器本地执行，不能映射成已存在的后端操作。不要直接从页面名称推断 API。新模块的详细对接内容以其 `contracts/API_HANDOFF.md` 为准；本指南只提供评审检查项，不复制模块契约事实。
