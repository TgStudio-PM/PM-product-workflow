# 模块 API 对接记录

本文件是本模块前后端对接信息的单一权威记录，适用于任意技术栈。仅在需要讨论服务端数据或行为时复制使用；它是可选模块文件，不要求每个原型都填写。

## 使用规则

- 先记录原型当前实现及其证据，再单独记录服务端待确认项；原型字段不自动等于服务端字段。
- URL、HTTP 方法、认证、服务端字段和生产行为在双方确认前一律标记为“待确认”，不得根据页面名称、按钮文案或 mock 推断。
- 服务端字段、接口及其实现细节由前端与后端责任人共同确认；业务含义、规则和流程以模块事实文件为依据，并由产品负责人确认。接口讨论不得自行改变或覆盖产品已确认的业务语义；发现冲突时先更新并确认相应模块事实，再确认接口映射。
- 只有相关责任人确认的具体内容才可标为“已确认”：服务端字段、接口及实现细节由前后端共同确认，业务含义和规则由产品负责人确认。填写确认人、日期和依据；不同字段或操作可处于不同状态。
- 验证状态与契约确认状态分开填写。文档、静态检查或 mock 演示不代表接口联调或生产验收。
- 责任人或确认日期尚未指定时填写“未指定”，不要留空；验证尚未执行时填写“未验证”，不要留空。已指定的责任人与日期以及已执行的验证，应填写实际信息和结果。
- 有开发实现或反馈输入时，分别记录其来源、源码提交与实际运行环境版本、反馈日期与适用版本；源码提交与运行环境版本分开，环境未核对不要写“已运行/联调”。
- 版本未提供写“待确认”，无此类输入写“不适用”；来源或版本未知的开发反馈不得覆盖已确认需求或契约。差异链接既有模块 `CURRENT.md`、业务规则或决策；责任人未确认前保持待确认，并保留原确认与验证分层，不新增状态、新表或重复事实库。
- 本记录维护完整的对接细节。模块其他文档只链接到此处，不复制接口事实；规则、流程、决策等仍以各自模块事实文件为准。
