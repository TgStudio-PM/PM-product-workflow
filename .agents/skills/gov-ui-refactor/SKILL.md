# Tg Studio · UI 定向改造

将明确的界面需求或已选定的评审项落实为现有原型代码。先核对项目入口、目标版本、未提交改动、设计规范、受影响页面与组件，以及本轮允许的修改范围。已有工程直接修改实际加载的源码；只有明确需要独立页面时才另行输出 HTML，不能把独立预览当作导航已接入。

独立复制此 Skill 无需保留工作流仓库目录。优先读取使用者提供的规范及 Profile 本地路径；在线默认预设仅为可选参考。无法获取时说明未检查范围，继续实施已有明确依据的改动，不声称使用了未读取的规范。

1. 锁定用户实际查看的入口：地址或文件、导航点击路径、角色/页面状态及相关路由参数。写入前核对源码根目录、适用的分支/worktree 和目标文件实际位置；有运行服务时用可取得的启动配置、进程或加载资源证据核对其源码目录，不凭端口或同名文件推断。源码位置不明先定位；仅运行环境不可核实时，可修改明确源码并将入口生效标待验证，不能用另一副本的通过结果证明当前入口已修复。沿用现有技术栈和组件体系，包括 Element UI / Element Plus；保留路由、字段、业务规则、数据来源和用户现场。
2. 平台适用条款优先，其次是项目确认的设计与组件约定，再按需参考可选 [gov-enterprise-cn Profile](https://github.com/TgStudio-PM/PM-product-workflow/blob/main/profiles/gov-enterprise-cn/PROFILE.md)。记录实际采用的来源与版本；缺少依据时不承诺平台合规。没有确定视觉方向的整体重设计，先明确方向再扩大实施。
3. 沿实际入口追到路由、页面/子组件及样式导入；能运行时检查目标元素是否匹配、实际生效声明和覆盖来源。只改本轮涉及的样式与交互，在原归属位置修正，避免文件末尾反复追加覆盖或无依据使用 `!important`。共享组件或样式检查实际调用处；移动、移除或改为按需加载时核对原入口和跨页使用，不按目录推断作用域。业务调整或超范围问题单列待确认，明确的独立部分继续。
4. 从用户的导航入口重走原触发步骤，再按需检查直达/刷新和受影响的共享页面。按实际控件选择空/长内容、禁用/编辑及相关桌面尺寸；原生选择控件不直接套普通文本框尺寸，固定区域核对滚动容器、遮挡和真实指针点击。保留原用户状态，不为复核清空草稿。记录本次版本、入口、状态、视口/缩放和前后可比证据；按项目现有命令做相关回归，测试与构建单列，不能代替页面生效复核。无法运行时明确待验证，不声称修复已在导航生效。

## 改了仍未生效

先区分：改动未被当前入口加载、样式已加载但被覆盖、元素/角色状态不匹配、布局或点击被遮挡、查看的是旧构建/旧包。用对应的导入、加载资源、匹配规则、计算样式或交互读数定位；没有证据不默认归因缓存，不反复重启、清缓存或重打包。连续两次等价尝试无效即停止堆样式，保留复现并一次验证一个原因；已记录的无效方案不重试。

原型页面中的说明服务实际操作，不默认插入开发说明、版本页脚或重复提示；保留用户要求及必要文案。独立文件使用授权输出位置，保留已有文件。

回传改动位置、对应需求/发现项、实际查看入口及其源码对应依据、页面复核、机器验证和遗留问题。证据写入已有任务或复核记录，不新建必填台账；事实或规则确有变化时增量同步，不因样式调整重写整套业务文档。
