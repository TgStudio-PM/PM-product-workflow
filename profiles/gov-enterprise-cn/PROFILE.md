# gov-enterprise-cn

面向中文政务与复杂 B 端 Web 管理产品的可选评审预设，帮助产品经理检查业务原型中的术语、流程、数据呈现和操作反馈。开发者可协作使用。

这是 Tg Studio 经验形成的检查清单，不代表政府部门、行业主管单位或政务平台的官方标准，也不替代项目提供的规范。使用者可不采用本预设，也可在自己的 `DESIGN_PROFILE.md` 中记录适用范围与项目覆盖项。

## 采用顺序

1. 项目提供且适用的权威平台硬规范及具体条款。
2. 项目已确认的业务规则、设计决策和组件约定。
3. 本 Profile 中适用于当前页面的检查点。
4. 评审者的主观体验建议。

证据冲突或不足时标记“待确认”，不自行裁定。逐项判断页面是否适用；不要要求每页都具备表格、复杂表单、材料清单或审批功能。静态证据无法证明的行为应标为待验证。

| 编号 | 检查点 | 可观察问题 |
| --- | --- | --- |
| GE-01 | 术语与状态 | 同一业务概念在查询、列表、详情和操作结果中是否使用一致名称？状态是否与已确认规则冲突？ |
| GE-02 | 查询与表格 | 适用时，查询项是否对应列表字段；筛选、清空、排序、分页和返回后的条件保持是否可理解？ |
| GE-03 | 行动与流程 | 页面是否说明当前事项、所需动作、办理角色和下一步？缺少依据时记录待确认，不补造流程。 |
| GE-04 | 表单与校验 | 适用时，必填、格式、条件字段、错误位置及修正方式是否清晰且有规则依据？ |
| GE-05 | 材料清单 | 适用时，材料名称、要求、必需/可选状态和缺项反馈是否易辨认；不虚构法定要求。 |
| GE-06 | 角色与权限提示 | 页面是否说明操作角色或范围？没有权限和后端证据时，不宣称真实权限已生效。 |
| GE-07 | 高影响操作 | 删除、撤回、提交等操作是否呈现影响并提供适当防误操作反馈？ |
| GE-08 | 结果反馈与追溯 | 完成、失败、处理中或无结果时，是否有清楚反馈；不得假设生产审计能力。 |
| GE-09 | 信息密度与可读性 | 高频信息是否便于扫描；字段、状态和操作是否易区分？ |
| GE-10 | 窄视口与适配 | 目标视口内内容与操作是否可访问，有无遮挡、溢出或不可操作元素？注明未测环境。 |

## 评审分类与证据

- **错误**：有证据表明实现缺陷，或与已确认业务规则、术语、流程冲突。
- **平台不合规**：引用权威来源、适用范围和具体条款；缺少任一项时列待确认或一般建议。
- **主观审美优化**：供产品判断的一般体验建议，不伪装成业务错误或平台要求。
- **Profile 偏差（可选记录）**：与本预设不一致，不自动代表错误或平台不合规。

正式结论记录位置、现象、证据/规则编号、影响、建议和待确认项。可用同目录的[评审模板](REVIEW_TEMPLATE.md)。事实写“已确认”或“待确认”；只有产品负责人明确允许时才写“假设”。

## 原型边界

原型证据仅说明指定版本可观察的页面和交互。没有后端、权限模型或接口证据时，不推断数据持久化、身份鉴别、权限控制、审计留痕或生产合规状态。注明实际检查的页面、环境和视口。
